# 文档编写规范

> 适用于所有 AI 生成或协助修改的 Forge 项目文档。

---

## 1. 核心原则：只写最终形态

- **不写推导过程**。删除所有"为什么选 X 而不是 Y"、"曾经试过 Z 但失败了"、"经讨论后决定"等论证性文字。
- **不写迭代历史**。删除版本回溯、修订记录、"之前是这样后来改成那样"的叙述。
- **不写对话痕迹**。删除"你建议"、"我同意"、"AI 提出"等双主体交流痕迹。

## 2. 允许保留的内容

- 直接的架构陈述（是什么、边界在哪、职责是什么）。
- 接口定义与类型签名（输入、输出、错误码）。
- 迁移步骤与任务分解（做什么、顺序、验证标准）。
- 设计红线与禁止项（不能做什么、越界后果）。
- 已验证的技术参数（版本号、阈值、枚举值）。

## 3. 常见需删除的句式

| 删除 | 改为 |
| :-- | :-- |
| "我们经过讨论决定..." | 直接陈述决策 |
| "为什么不使用 X" | 删除整段，只保留最终方案 |
| "最初设想...但后来发现..." | 删除，只保留最终方案 |
| "这一步可以优化，但当前先..." | 删除括号内补充，或移到 TODO |
| "参考了 A 和 B，最终选择 C" | 只保留"使用 C" |
| "已经踩过的坑" | 删除 |

## 4. 文档定位说明

> 段落允许存在，但**只陈述本文档是什么、承接哪份文档**，不解释为什么这样拆分。

示例：
```markdown
> 本文是沉淀场域的落地方案，承接 `沉淀学习系统设计.md` 的阶段逻辑。
> 交付物：设计规范 + 任务分解。
```

禁止：
```markdown
> 之所以单独拆出本文，是因为落地方案和设计逻辑需要解耦...
```

## 5. 表格与列表

- 表格只呈现**最终规约**，不写"原因"列来论证为什么要这么做。
- 列表只呈现**需要做什么**，不写"为什么做"的前置说明。

## 6. 引用外部决策

- 可以引用另一份文档的章节（如"见 `后端架构方案.md` §4.3"）。
- **不允许**在本文档内复述那份文档的推导过程来支撑本文档的决策。

## 7. 执行检查

每完成一篇文档修改，快速扫描以下关键词：

`为什么`、`之所以`、`经过`、`讨论决定`、`试过`、`踩过`、`最初`、`后来`、`迭代`、`修订`、`参考了`、`对比了`、`否决`、`放弃`

出现即删除或改写。
