# 代码编写规范

> 适用于所有 AI 生成或协助修改的 Forge 项目代码。

---

## 1. 注释：只写最终形态

注释描述代码当前是什么，不描述它曾经是什么、如何变成现在这样。

- **不写推导过程**。删除所有"为什么选 X 而不是 Y"、"曾经试过 Z 但失败了"、"经讨论后决定"等论证性文字。
- **不写迭代历史**。删除"废弃 X 改为 Y"、"之前是这样后来改成那样"、"原逻辑已移除"等版本叙述。
- **不写对话痕迹**。删除"你建议"、"我同意"、"AI 提出"、"按需求改为"等双主体交流痕迹。
- **不注释 diff**。只对阅读本次改动的人有意义的注释一律不写，改动背景放进提交信息或 PR 描述。

| 删除 | 改为 |
| :-- | :-- |
| `# 废弃旧的 X 方案，改为 Y` | 直接描述 Y 的行为，或不写注释 |
| `# 之前用 A 实现，现改用 B` | 删除 |
| `# 按讨论决定新增此参数` | 删除 |
| `# 修复了 X 情况下的 bug` | 删除，只保留描述当前行为的注释 |

默认不写注释，靠命名表达意图；确需注释时保持简短、陈述当前事实。

## 2. 逻辑：只写最终形态

修改代码时的心智模型是「这个单元的最终行为应该是什么」，不是「在上一版上打补丁」。方案换代时重写受影响的最小单元到最终形态，而不是在旧实现周围加修正层。

- **不留死分支**：条件判断针对的输入 / 状态在新方案下不可能出现时，删除该分支，不留「以防万一」。
- **不双路径**：换存储 / 命名 / 格式方案后，读写只走新路径，不同时读旧位置再合并。
- **不补丁套补丁**：不在函数入口 / 出口加 if 修正旧逻辑的结果（「先算错再修正」），而是重写让它一次算对。
- **不留孤儿代码与残留状态**：改动后不再被使用的函数 / 参数 / 字段 / 标志位 / import 随本次改动删除；新流程不再读写的状态不保留初始化 / 序列化 / 判断。
- **契约同步**：行为改了，类型注解、默认值、命名、提示词 / 文档里的描述同步改到最终形态，不靠运行时容错掩盖不一致。

检验标准：把本次改动后的代码当作第一次就这么写来读——若某段逻辑只有知道上一版才能解释它为什么存在，它就是迭代残留，删除或重写。

## 3. 结构：高内聚低耦合

新增或修改功能时必须遵循：

- 单一职责：一个模块 / 函数只做一件事，相关逻辑聚在一处。
- 依赖显式：跨模块依赖走明确的接口，不隐式共享状态。
- 边界不越位：遵循 AGENTS.md「放代码的边界」，场域逻辑不进 `core/`，工具逻辑不进 `fields/`。

## 4. 不写多余的兜底与兼容

- 已明确不需要的旧方案，直接按新方案实现，不保留旧路径、不写兼容分支、不留降级开关。
- 不为不可能出现的场景写防御性代码。
- 例外：兜底 / 兼容是系统性设计要求时（如对外 API 版本兼容、外部服务不可用的降级策略）才保留，且需在对应设计文档中有明确依据。

## 5. 执行检查

每完成一次代码修改，扫描新增注释中的关键词：

`废弃`、`改为`、`之前`、`原来`、`旧版`、`兼容旧`、`按需求`、`讨论决定`、`修复了`、`不再`

出现即删除或改写为对当前行为的陈述。
