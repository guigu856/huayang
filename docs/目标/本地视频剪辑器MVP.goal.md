# 本地视频剪辑器 MVP Goal

## 推荐执行版（中文，可直接复制）

/goal 在 `D:\project\video_create` 交付 `components/video_editor/` 本地视频剪辑器组件：用户可在本机浏览器导入视频、图片和音频，通过可增删、改名和重排的 visual/audio 多轨时间线完成拖放、左右裁剪、分割、文本、画中画、位置、尺寸、旋转、不透明度和音量编辑；新增 visual 素材统一按主视频规则居中等比适配画布，用户可从属性面板或预览画布选框调整 Transform；Track 只保存处理域，Clip 以 media/text 表达内容，画中画由 visual 轨顺序与显式 Transform 表达；工程原子保存为带 `schema_version: "2.0"`、id 与 revision 的声明式 JSON；Codex、Claude Code、Cursor 等 Agent 可通过同一 `VideoEditorService`、`video-editor` CLI 和 `/api/v1` HTTP 命令批次读取与修改工程；浏览器使用原生 HTML、CSS、ES Modules 和媒体元素组合预览；持久化单并发队列仅在导出任务中调用 FFmpeg，并以 ffprobe 验证 H.264 MP4。

验证：先运行 `Test-Path .git` 并如实记录当前工作区没有 `.git` 元数据；运行 `uv sync --extra dev`；运行 `uv run pytest tests/test_video_editor_core.py tests/test_video_editor_media.py tests/test_video_editor_render.py tests/test_video_editor_jobs.py tests/test_video_editor_api.py tests/test_video_editor_cli.py tests/test_video_editor_web.py`、`uv run ruff check components/video_editor tests` 和 `uv run mypy`；运行 `Get-ChildItem components/video_editor/web/*.js | ForEach-Object { node --check $_.FullName }` 检查 ES Modules 语法；启动 `uv run video-editor serve --host 127.0.0.1 --port 8765`，用浏览器完成新建工程、三类素材导入、visual/audio 轨新增、改名、重排和删除、多轨拖放、播放头连续拖动、左右裁剪、分割、文本、叠加 visual 素材默认使用主视频适配、预览画布拖动与四角等比缩放、属性修改为画中画、刷新恢复、导出和下载，并保存截图与服务日志；确认在所有 visual 轨中，tracks 数组位置更靠前者在网页与导出中均处于更高视觉层，audio 轨位置不改变视觉合成；对同一夹具分别调用 Python、CLI 和 HTTP，比较规范化 `EditorProject` 与错误码；并发提交相同 expected_revision 的命令批次，证明只增加一次 revision；放置超过 60 秒的 `.project.lock`，证明下一次写入回收陈旧锁；重启服务后证明 queued 任务继续执行、原 running 任务转为带 `render_interrupted` 的 failed；最后用 `ffprobe -v error -show_entries format=duration,size:stream=codec_name,width,height -of json` 检查真实 MP4。

约束：工程协议固定为 `EditorProject` 的 `schema_version: "2.0"`、id、name、revision、canvas、assets 与 tracks；Track 固定为 id、`media_domain: visual|audio`、name 与 clips，tracks 数组按网页从上到下排列，在所有 visual 轨中数组位置更靠前者层级更高，audio 轨位置不参与视觉层级；Clip 固定以 `kind: media|text` 决定 `asset_id` 或 `text`；片段时间字段固定为浮点秒 `timeline_start`、duration 与 `source_in`；几何字段固定为 x、y、width、height、rotation 与 opacity；所有工程写入固定为 `CommandBatch` 的 expected_revision 与 commands；一次成功批次只增加一次 revision，任一子命令失败时保持原工程；统一响应固定为 `ok/data` 或 `ok/error`，错误包含 code、message 与 details；网页、Python、CLI 和 HTTP 共用 `VideoEditorService`；浏览器预览不启动 FFmpeg；FFmpeg 只在持久化单并发队列执行；源素材、已有工程和已验证成品受只读保护；前端文字使用中文且仅保留必要日志；账号、云同步、移动端、智能字幕、复杂特效、模板市场、多人协作和远程渲染保持在 MVP 范围之外。

边界：产品代码严格限定在 `components/video_editor/`，测试严格限定在 `tests/test_video_editor_core.py`、`tests/test_video_editor_media.py`、`tests/test_video_editor_render.py`、`tests/test_video_editor_jobs.py`、`tests/test_video_editor_api.py`、`tests/test_video_editor_cli.py` 与 `tests/test_video_editor_web.py`；运行产物写入测试临时目录或 `output/editor/`；依赖、CLI 入口或环境说明需要同步时才修改 `pyproject.toml`、`uv.lock`、`.env.example`、`docs/命令速查.md`、`docs/后端架构方案.md` 和视频编辑器组件文档；保持 `components/video_download/`、`components/material_acquisition/`、既有相关测试、既有输出与无关文档原样；每一行修改都对应本 Goal、PRD 或架构文档中的交付。

Iteration policy: 按“Pydantic 工程与命令契约 → `VideoEditorService` 与原子 `ProjectStorage` → 媒体导入与 ffprobe → CLI 与 FastAPI 薄适配器 → 原生网页时间线与组合预览 → `RenderPlan` 与持久化单并发队列 → 故障和性能证据”的顺序交付垂直切片；每个切片先增加失败测试，再做最小实现，运行最小相关检查后进入下一切片；失败时先读取测试、结构化错误、服务日志、浏览器记录或 ffprobe 输出，每个检查点最多进行 3 轮基于新证据的聚焦修复，仍未通过时记录可复现命令、当前证据和最小阻塞点。

完成条件：PRD 中五个验收剧本全部有可重复证据；七个视频编辑器测试文件、ruff、mypy 与所有 ES Modules 语法检查通过；浏览器端到端闭环可重复；Python、CLI 与 HTTP 对同一命令批次产生相同 `EditorProject` 语义；revision 冲突、批次失败、陈旧锁、素材错误、服务重启、渲染失败和取消均返回稳定结果并保留完整数据；持久化队列保持跨进程单工作线程；浏览器组合预览与导出帧满足架构文档的时间与几何容差；性能基准逐项记录目标、实测值和环境；ffprobe 确认输出 MP4 的视频流、尺寸、时长及预期音频流；交接包含改动文件、同步文档、验证命令、剩余风险和下一步。

暂停条件：实现需要扩大到已排除的产品范围、再次改变已确定的 schema 2.0、revision、浮点秒、Transform、CommandBatch 或统一响应语义、改变既有下载与素材获取组件公开契约、引入远端服务或账号凭证、把服务暴露到非回环网络、采用不可逆工程迁移、覆盖用户素材或既有成品、性能目标需要改变产品边界，或同一阻塞在 3 轮新证据修复后仍存在时，保存现场证据并等待产品或架构决策。

默认选择理由：该范围同时证明浏览器人工剪辑、Agent 程序化剪辑和 FFmpeg 真实渲染三条核心链路，并把后续扩展限制在稳定工程、命令、服务和渲染边界之后。

## Goal Draft (English-compatible)

/goal Deliver `components/video_editor/` inside `D:\project\video_create`: a user opens the local browser editor, imports video, image, and audio assets, and edits a multi-track timeline with visual/audio tracks that can be added, renamed, reordered, and deleted; support drag, left and right trim, split, text, picture-in-picture, position, size, rotation, opacity, and volume; keep processing domain on Track, content kind as media/text on Clip, and express picture-in-picture through visual-track order plus Transform; atomically save each project as declarative JSON with `schema_version: "2.0"`, id, and revision; let Codex, Claude Code, Cursor, and other agents read and edit the same project through `VideoEditorService`, the `video-editor` CLI, and `/api/v1` HTTP command batches; use native HTML, CSS, ES Modules, and browser media elements for composite preview; run FFmpeg only inside a persistent single-concurrency export queue and verify the H.264 MP4 with ffprobe.

Verification: run `Test-Path .git` and record that the current workspace has no `.git` metadata; run `uv sync --extra dev`; run `uv run pytest tests/test_video_editor_core.py tests/test_video_editor_media.py tests/test_video_editor_render.py tests/test_video_editor_jobs.py tests/test_video_editor_api.py tests/test_video_editor_cli.py tests/test_video_editor_web.py`, `uv run ruff check components/video_editor tests`, and `uv run mypy`; run `Get-ChildItem components/video_editor/web/*.js | ForEach-Object { node --check $_.FullName }` for ES Modules syntax; start `uv run video-editor serve --host 127.0.0.1 --port 8765`, complete project creation, all three asset imports, visual/audio track add, rename, reorder, and delete operations, multi-track drag, continuous playhead scrubbing, left and right trim, split, text, picture-in-picture on an upper visual track, property editing, reload recovery, export, and download in a browser, and capture screenshots plus service logs; prove that the first visual track in the tracks array is the highest visual layer in both preview and export while audio-track positions do not affect visual compositing; execute the same fixture through Python, CLI, and HTTP and compare normalized `EditorProject` values and error codes; submit concurrent command batches with the same expected_revision and prove that revision increases once; place a `.project.lock` older than 60 seconds and prove that the next write reclaims it; restart the service and prove that queued jobs resume while a prior running job becomes failed with `render_interrupted`; finally inspect the real MP4 with `ffprobe -v error -show_entries format=duration,size:stream=codec_name,width,height -of json`.

Constraints: keep the project contract at `schema_version: "2.0"` with id, name, revision, canvas, assets, and tracks; keep Track as id, `media_domain: visual|audio`, name, and clips, with the tracks array ordered top-to-bottom, earlier visual tracks above later visual tracks, and audio-track positions excluded from visual compositing; keep Clip content as `kind: media|text` with the matching `asset_id` or `text`; keep clip timing as floating-point seconds in `timeline_start`, duration, and `source_in`; keep geometry as x, y, width, height, rotation, and opacity; express every project write as a `CommandBatch` with expected_revision and commands; increment revision once for a successful batch and preserve the original project after any child command fails; keep responses in `ok/data` or `ok/error` form with code, message, and details; share `VideoEditorService` across the browser, Python, CLI, and HTTP paths; keep FFmpeg out of browser preview and run it only in the persistent single-concurrency queue; protect source assets, existing projects, and verified outputs; use Chinese frontend copy and only necessary logs; keep accounts, cloud sync, mobile editing, AI subtitles, advanced effects, template markets, collaboration, and remote rendering outside the MVP.

Boundaries: keep product code under `components/video_editor/`; keep tests in `tests/test_video_editor_core.py`, `tests/test_video_editor_media.py`, `tests/test_video_editor_render.py`, `tests/test_video_editor_jobs.py`, `tests/test_video_editor_api.py`, `tests/test_video_editor_cli.py`, and `tests/test_video_editor_web.py`; place runtime products in test temporary directories or `output/editor/`; update `pyproject.toml`, `uv.lock`, `.env.example`, `docs/命令速查.md`, `docs/后端架构方案.md`, and the video editor component document only when dependencies, entry points, environment fields, or public contracts require synchronization; preserve `components/video_download/`, `components/material_acquisition/`, existing related tests, existing outputs, and unrelated documents; trace every changed line to this Goal, the PRD, or the architecture document.

Iteration policy: deliver vertical slices in this order: Pydantic project and command contracts, `VideoEditorService` and atomic `ProjectStorage`, media import and ffprobe, thin CLI and FastAPI adapters, native web timeline and composite preview, `RenderPlan` and the persistent single-concurrency queue, then fault and performance evidence; add a failing test before each slice's smallest implementation and run the narrowest relevant checks before continuing; inspect tests, structured errors, service logs, browser records, or ffprobe output before each repair; perform at most three focused evidence-driven repair rounds per failed checkpoint, then record the reproduction command, current evidence, and smallest blocker.

Stop when: all five PRD acceptance scripts have repeatable evidence; the seven video editor test files, ruff, mypy, and every ES Modules syntax check pass; the browser end-to-end loop is repeatable; Python, CLI, and HTTP produce identical `EditorProject` semantics for the same command batch; revision conflicts, failed batches, stale locks, media errors, service restarts, render failures, and cancellation preserve complete data and return stable results; the persistent queue keeps one worker across processes; browser composite preview and exported frames meet the architecture's time and geometry tolerances; every performance benchmark records its target, measured value, and environment; ffprobe confirms the output video stream, dimensions, duration, and expected audio stream; the handoff lists changed files, synchronized documents, verification commands, residual risks, and next steps.

Pause if: implementation requires expanding into an excluded product area, changing the established schema 2.0 contract again, changing revision, floating-point-second, Transform, CommandBatch, or response semantics, changing the public contract of an existing download or acquisition component, introducing a remote service or account credential, exposing the service beyond loopback, applying an irreversible project migration, overwriting user assets or verified products, changing the product boundary to meet a performance target, or continuing after the same blocker remains through three evidence-driven repair rounds; preserve the evidence and wait for a product or architecture decision.
