# 图片获取与媒体预处理

## 组件边界

`components.image_acquisition` 负责从公开图片库搜索、取得、验证图片，并保存逐素材来源与授权元数据。`components.media_preprocessing` 负责在输入哈希固定后执行声明式 FFmpeg 操作，并保存父媒体与派生媒体的哈希关系。

两个组件只执行确定性 I/O 和媒体处理。素材选择、画面语义判断、剪辑规划、抠像和合成由对应工作流阶段负责。

## 图片获取

### 来源

图片来源为 Wikimedia Commons 的 MediaWiki Action API：

- API：`https://commons.wikimedia.org/w/api.php`
- API 说明：`https://commons.wikimedia.org/wiki/Commons:API`
- 图片信息模块：`https://www.mediawiki.org/wiki/API:Imageinfo`
- 访问方式：公开 API，无 API Key

搜索使用文件命名空间和 `imageinfo` 的 `url`、`mime`、`size`、`extmetadata` 字段。组件只保留同时具有作者、授权名称、授权链接和来源页面的 JPEG、PNG、WebP 候选。

组件通过 `iiurlwidth` 获取受控宽度的 Commons 派生图用于剪辑，溯源记录同时保存原始文件地址与实际取得地址。

候选的授权字段是来源 API 的逐素材元数据记录。发布前仍需结合用途、地区、署名要求和来源页面完成项目侧权利确认。

### Agent API

固定流程为：

```text
list_sources -> search -> acquire
```

```python
from pathlib import Path

from components.image_acquisition import (
    ImageAcquisitionConfig,
    ImageAcquisitionService,
)

service = ImageAcquisitionService(
    ImageAcquisitionConfig(output_dir=Path("output/images"))
)
search = service.search("Tokyo night city", limit=3)
result = service.acquire(search.candidates[0].candidate_ref)
```

- `search(query, limit)` 返回公开候选和不透明 `candidate_ref`。
- 公开候选包含标题、作者、来源页面、授权名称、授权链接、MIME 和尺寸。
- 下载地址只写入私有搜索记录。
- `acquire(candidate_ref)` 只读取对应搜索记录中与引用摘要一致的候选。

### 获取验证

取得图片时依次验证：

1. 引用格式、搜索令牌和候选载荷摘要一致。
2. 下载地址及重定向终点属于 `upload.wikimedia.org` 的 HTTPS 地址。
3. 响应未超过 `max_download_bytes`。
4. HTTP `Content-Type`、搜索候选 MIME 和 Pillow 解码格式一致。
5. Pillow 完整解码成功，解码尺寸与搜索候选尺寸一致。
6. 计算文件 SHA-256 后写入派生文件名和溯源记录。

图片与 JSON 溯源记录先写入输出根目录下的临时目录，再通过同卷原子替换提交。JSON 提交失败时删除已提交的图片。

### 图片输出

```text
output/images/
  searches/search_<token>.json
  downloads/wikimedia_<asset_id>_<sha12>.<ext>
  provenance/wikimedia_<asset_id>_<sha12>.json
```

溯源记录包含：

- 查询词与 `candidate_ref`；
- 来源、素材 ID、标题、作者、来源页面和原始文件地址；
- 授权名称、授权链接和记录适用范围；
- 本地绝对路径、SHA-256、字节数、MIME 和解码尺寸；
- UTC 获取时间。

### 图片错误码

`ImageAcquisitionError.code` 的主要取值：

- `invalid_query`
- `invalid_limit`
- `invalid_config`
- `search_failed`
- `candidate_ref_invalid`
- `candidate_ref_expired`
- `download_url_invalid`
- `download_failed`
- `download_too_large`
- `invalid_media`
- `http_failed`
- `output_unavailable`

## 声明式媒体预处理

### Agent API

```python
from components.media_preprocessing import (
    MediaOperation,
    MediaPreprocessingService,
    MediaPreprocessRequest,
)

request = MediaPreprocessRequest(
    operation=MediaOperation.FRAME_EXTRACT,
    input_path="input.mp4",
    input_sha256="<64位小写SHA-256>",
    timestamp_seconds=1.25,
)
result = MediaPreprocessingService().execute(request)
```

`MediaPreprocessRequest` 禁止额外字段。每个操作只接受表中参数：

| 操作 | 必填参数 | 输出 | 确定行为 |
| :-- | :-- | :-- | :-- |
| `video_trim` | `start_seconds`、`duration_seconds` | MP4 | 第一视频流和可选第一音频流，H.264/AAC 重编码 |
| `audio_trim` | `start_seconds`、`duration_seconds` | M4A | 第一音频流，AAC 重编码 |
| `frame_extract` | `timestamp_seconds` | PNG | 第一视频流指定时间的一帧 |
| `scale_pad` | `width`、`height`、`pad_color` | MP4 | 等比缩放后居中补边，第一视频流和可选第一音频流，H.264/AAC 重编码 |

`scale_pad` 的输出宽高必须为偶数。`pad_color` 接受 `black`、`white` 或 `0xRRGGBB[AA]`。组件按声明值执行；缺少必填参数、出现无关参数、时间越界或尺寸不合规时产生明确错误。

### 执行与验证

1. 读取输入文件并验证 `input_sha256`。
2. 使用 ffprobe 验证输入流结构和时间范围。
3. FFmpeg 向输出根目录内的临时文件执行一次声明操作。
4. 视频和音频结果使用 ffprobe 验证；PNG 使用 Pillow 完整解码验证。
5. 验证裁剪时长、`scale_pad` 画布尺寸和目标流结构。
6. 计算派生 SHA-256，提交派生文件和 JSON 溯源记录。

预处理不会修改输入文件。输出文件名包含操作名与派生 SHA-256 前缀；重复执行时追加序号并保留已有文件。

### 预处理输出

```text
output/preprocessed/
  derivatives/<parent>_<operation>_<sha12>.<ext>
  provenance/<parent>_<operation>_<sha12>.json
```

溯源记录包含：

- 操作枚举和实际应用的声明参数；
- 父媒体绝对路径与输入 SHA-256；
- 派生媒体绝对路径、SHA-256、字节数和 MIME；
- 派生媒体的时长、尺寸、视频编码和音频编码；
- `derived_from_parent` 关系和 UTC 创建时间。

### 预处理错误码

`MediaPreprocessingError.code` 的主要取值：

- `input_missing`
- `input_unreadable`
- `input_sha256_mismatch`
- `dependency_missing`
- `required_stream_missing`
- `time_range_out_of_bounds`
- `timestamp_out_of_bounds`
- `invalid_media`
- `ffmpeg_failed`
- `invalid_output`
- `output_unavailable`

## 运行要求

- Python 3.11+
- Pillow 11+
- Pydantic 2.9+
- FFmpeg 和 ffprobe 位于 `PATH`
