# 本地视频剪辑器组件

## 组件入口

本地视频剪辑器位于 `components/video_editor/`，提供四个使用入口：

- 浏览器工作台：素材库、组合预览、属性面板、多轨时间线与导出任务。
- Python API：`VideoEditorService` 与领域模型。
- Agent CLI：`video-editor`。
- HTTP API：`/api/v1`。

四个入口共享 `EditorProject`、`CommandBatch` 与 `VideoEditorService`。网页和 Agent 的写入都携带 `expected_revision`。

## 启动网页

```powershell
uv sync --extra dev
uv run video-editor serve --host 127.0.0.1 --port 8765
```

浏览器打开 `http://127.0.0.1:8765`。默认工程目录为 `output/editor/projects`，也可通过全局参数或环境变量指定：

```powershell
uv run video-editor --root D:\video-projects serve
$env:VIDEO_EDITOR_ROOT = "D:\video-projects"
uv run video-editor serve
```

系统需从 `PATH` 找到 `ffmpeg` 与 `ffprobe`。
中文字幕优先使用 `VIDEO_EDITOR_FONT_PATH`，未配置时依次查找本机常见的微软雅黑、黑体、苹方、Noto CJK 与文泉驿字体。
网页使用 Web Audio GainNode 预览 0%–200% 音量，导出使用同一 `volume` 数值。
新增视频或图片进入任意 visual 轨时，默认使用与主视频相同的居中等比画布适配。选择当前可见片段后，可在属性面板修改 Transform，也可在预览画布拖动选框或四角控制点调整位置与等比尺寸；轨道顺序只控制视觉层级。

## Agent CLI

所有短命令在标准输出写入一个 JSON 对象，进度写入标准错误。成功和失败结构固定为：

```json
{"ok":true,"data":{}}
{"ok":false,"error":{"code":"ERROR_CODE","message":"错误信息","details":{}}}
```

### 工程

```powershell
uv run video-editor project create --name "短片工程"
uv run video-editor project list
uv run video-editor project show PROJECT_ID
```

指定画布：

```powershell
uv run video-editor project create --name "竖屏短片" --canvas-json '{"width":1080,"height":1920,"fps":30,"background_color":"#000000"}'
```

### 命令批次

```powershell
uv run video-editor command apply PROJECT_ID --file command-batch.json
Get-Content -Raw -Encoding utf8 command-batch.json | uv run video-editor command apply PROJECT_ID
```

`command-batch.json`：

```json
{
  "expected_revision": 0,
  "commands": [
    {"type": "track.add", "media_domain": "visual", "name": "主画面"},
    {"type": "track.add", "media_domain": "visual", "name": "画中画", "index": 0},
    {"type": "track.add", "media_domain": "audio", "name": "配乐"}
  ]
}
```

批次成功后整个工程的 `revision` 增加 1，并返回完整工程。调用方从返回值读取服务生成的 `track_id`、`asset_id` 与 `clip_id`。

### 素材

```powershell
uv run video-editor asset import PROJECT_ID D:\media\source.mp4 --expected-revision 1
```

素材复制到工程目录后由 `ffprobe` 探测，成功响应同时包含新素材与新工程快照。HTTP 与 CLI 使用同一条 4 GiB 单文件上限；HTTP 超限返回 `413` 与稳定错误码 `media_too_large`。

### 导出

```powershell
uv run video-editor render PROJECT_ID --expected-revision 3
uv run video-editor render PROJECT_ID --expected-revision 3 --output D:\exports\final.mp4
```

导出命令提交持久化任务、等待完成，并返回 `RenderJob`。输出为 H.264、`yuv420p` MP4；有音频片段时使用 AAC 48 kHz。

## Python API

```python
from pathlib import Path

from components.video_editor import VideoEditorService

service = VideoEditorService(Path("output/editor/projects"))
project = service.create("Agent 工程")
project = service.apply(
    project.id,
    {
        "expected_revision": project.revision,
        "commands": [
            {
                "type": "track.add",
                "media_domain": "visual",
                "name": "主画面",
            }
        ],
    },
)
```

公开服务接口：

```text
create(name, canvas=None) -> EditorProject
list() -> list[EditorProject]
get(project_id) -> EditorProject
apply(project_id, batch) -> EditorProject
```

## HTTP API

| 方法 | 路径 | 结果 |
| :-- | :-- | :-- |
| `GET` | `/api/v1/health` | 服务状态 |
| `GET` | `/api/v1/projects` | 工程列表 |
| `POST` | `/api/v1/projects` | 创建工程 |
| `GET` | `/api/v1/projects/{project_id}` | 完整工程 |
| `POST` | `/api/v1/projects/{project_id}/commands` | 原子执行命令批次 |
| `POST` | `/api/v1/projects/{project_id}/assets` | 上传并登记素材 |
| `GET` | `/api/v1/projects/{project_id}/assets/{asset_id}/content` | 素材内容与 Range 响应 |
| `POST` | `/api/v1/projects/{project_id}/renders` | 创建导出任务 |
| `GET` | `/api/v1/render-jobs/{job_id}` | 导出任务状态 |
| `DELETE` | `/api/v1/render-jobs/{job_id}` | 取消导出任务 |
| `GET` | `/api/v1/render-jobs/{job_id}/output` | MP4 与 Range 响应 |

成功响应为 `{"ok":true,"data":...}`，领域错误为 `{"ok":false,"error":{"code","message","details"}}`。OpenAPI 为工程、素材导入和渲染任务声明具体的 `data` 模型，Agent 可直接发现命令输入与成功响应结构。

## 工程与命令契约

工程顶层字段：

```text
schema_version = "2.0"
id, name, revision
canvas = {width, height, fps, background_color}
assets[]
tracks[] = {id, media_domain, name, clips[]}
```

片段字段：

```text
kind = media 或 text
timeline_start, duration, source_in
asset_id 或 text
transform = {x, y, width, height, rotation, opacity}
volume
```

命令类型：

```text
project.update
asset.add / asset.delete
track.add / track.update / track.move / track.delete
clip.add / clip.update / clip.delete / clip.split
```

`Track.media_domain` 只描述处理域：`visual` 轨接受视频、图片和文本片段，`audio` 轨接受音频片段。主画面、画中画和字幕是轨道名称或片段用途，不是轨道类型。`tracks` 数组按网页从上到下排列；在所有 visual 轨中，数组位置更靠前者层级更高，第一条 visual 轨是最高视觉层，audio 轨的位置不参与视觉合成。渲染器从最低 visual 轨向最高 visual 轨合成。`track.add.index` 可指定插入位置，`track.update` 修改名称，`track.move.to_index` 调整顺序。

visual 轨层级不自动产生画中画 Transform。画中画由用户或 Agent 显式写入较小的 `width`、`height` 及对应 `x`、`y`；新片段的默认 Transform 与所在 visual 轨位置无关。

`Clip.kind` 描述片段内容：`media` 必须且只能提供 `asset_id`，`text` 必须且只能提供 `text`。`clip.split.at` 是工程时间线上的绝对秒数，媒体片段的 `source_in + duration` 位于素材时长内。

## 本地数据

```text
output/editor/
├── projects/
│   └── PROJECT_ID/
│       ├── project.json
│       ├── assets/
│       └── renders/
└── render_jobs/
    └── RENDER_JOB_ID/
        ├── job.json
        ├── project.json
        └── request.json
```

- 工程写入使用 revision 校验、短时排他锁和同目录原子替换。
- 超过 60 秒的工程写锁按陈旧锁回收。
- 渲染任务保存不可变工程快照；服务重启时，排队任务继续执行，运行中任务记录为 `render_interrupted`。
- FFmpeg 写入临时 MP4，`ffprobe` 验证成功后原子发布，原有成品保持完整。
- 单次 FFmpeg 执行总时限默认为 3600 秒；超时先 terminate，3 秒后仍未退出则 kill，任务记录 `render_timeout`，队列继续处理下一项。
- 一个任务目录只持有一个跨进程渲染 worker 锁，渲染并发为 1。

## 扩展边界

- 新剪辑能力先增加领域模型与命令，再扩展浏览器适配和 `RenderPlan` 编译。
- `VideoEditorService` 不依赖 FastAPI、浏览器或 FFmpeg。
- `compile_render_plan` 只把工程快照编译为 FFmpeg argv、filtergraph 和临时支持文件。
- `FFmpegRenderer` 只负责进程、取消、验证和结果发布。
- `PersistentRenderQueue` 只负责任务持久化、恢复和单并发调度。

大工程的首要性能边界是原片随机定位、多层 FFmpeg filtergraph、完整工程列表读取和浏览器媒体解码。代理文件、缩略图、波形、工程摘要索引与独立渲染进程是对应扩展点。
