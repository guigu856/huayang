# Huayang 剪辑创作 Plugin

## 组件边界

Huayang 将项目中的视频下载、素材与 BGM 获取、参考分析、共享知识、分阶段创作、工程编译、渲染和成片检查统一暴露给宿主 Agent。

```text
Plugin
├── .codex-plugin / .claude-plugin   宿主清单
├── rules                            角色职责与阶段边界
├── skills                           当前阶段的分析和创作流程
├── .mcp.json                        stdio MCP 配置
└── video_create_plugin              工作流、知识、编译与 MCP 应用服务
```

Agent 负责语义判断和创作决策；组件负责可复现分析、资源 I/O、状态持久化、Schema 校验、工程编译和渲染检查。MCP Handler 只映射公共应用服务，不复制组件领域逻辑。

## 安装与启动

```powershell
uv sync --extra dev
uv run playwright install chromium
uv tool install --force --editable .
huayang-mcp
```

将精简后的 Rules、Skills、Schemas 与 MCP 清单安装到 Codex：

```powershell
uv run python -c "from pathlib import Path; from video_create_plugin.codex_install import build_codex_marketplace; print(build_codex_marketplace(Path.cwd()))"
codex plugin marketplace add "$env:LOCALAPPDATA\huayang\marketplace"
codex plugin add huayang@huayang-local
```

`huayang-mcp` 使用 stdio。Codex Marketplace 包与 Claude Code 项目插件从同一份 `.mcp.json` 启动该服务。Claude Code 清单可执行结构校验：

```powershell
claude plugin validate .
```

运行前可配置：

```powershell
$env:HUAYANG_OUTPUT_ROOT = "D:\huayang-output"
$env:HUAYANG_MEDIA_ROOTS = "D:\media;E:\shared-media"
$env:HUAYANG_ADMIN_PORT = "8788"
```

- `HUAYANG_PROJECT_ROOT` 指定项目根目录。
- `HUAYANG_RESOURCE_ROOT` 指定 rules、skills 与 schemas 的资源根目录。
- `HUAYANG_OUTPUT_ROOT` 保存任务、对象、知识索引和任务派生媒体。
- `HUAYANG_MEDIA_ROOTS` 是 MCP 可读取的外部媒体根目录。Plugin 输出目录始终属于允许范围。
- `HUAYANG_ADMIN_PORT` 指定后台端口，默认 `8788`。
- FFmpeg、ffprobe、`huayang` 与 `huayang-mcp` 需位于 `PATH`。

## 后台管理

安装后在终端只输入插件名即可启动后台并自动打开浏览器：

```powershell
huayang
```

后台只监听 `127.0.0.1`，提供以下管理视图：

- Rules 与 Skills：查看、创建和编辑全部资源；内置资源保留删除保护，自定义资源可删除。
- 创作产物与学习产物：按产物分类查看允许类型的文件及内容预览。
- 工作流任务与 Artifact：读取主工作流和参考学习发布校验工作流的任务、状态与产物内容。

资源编辑使用内容 SHA-256 进行并发校验并通过原子替换落盘；产物浏览只读，不改变工作流状态。

MCP Context Catalog 直接读取后台维护的资源根，因此保存后立即返回新版本。Codex 原生 Skills 来自 Marketplace 安装快照；Rule/Skill 变更后重新执行 `build_codex_marketplace` 并新建 Codex 任务，宿主侧即可加载新快照。

## 渐进式阶段上下文

宿主按以下顺序调用：

1. 读取 `huayang://catalog`。
2. 创建任务并调用 `workflow_get_stage_envelope`。
3. 只读取 Envelope 返回的当前角色 rule、skills、Schema 和冻结输入。
4. 使用 `stage_access_handle` 调用当前阶段工具。
5. 提交主产物，用户确认后记录 FreezeRecord，再进入下一阶段。

`stage_access_handle` 绑定任务、阶段、revision、工具权限和有效期。阶段重开后，旧句柄失效，引用旧冻结版本的后继阶段标记为 `stale`。

## 三类任务

### 参考视频学习

```text
来源解析或下载
→ 视频与音频确定性证据
→ 多维语义分析
→ 参考报告
→ 用户确认并冻结
→ 发布共享知识
```

自动帧差峰值只表示复核候选。语义报告区分主画面切换、镜内图层动作和整体效果，覆盖完整时间线，并为事实、推测、观点和尚未确认的信息保留状态和证据引用。

### 原创视频

```text
用户想法
→ 总体方案
→ 用户确认并冻结
→ 素材与 BGM 筹备
→ 用户确认并冻结
→ 可执行剪辑规格
→ 用户确认并冻结
→ 能力预检与确定性编译
→ 渲染与成片检查
```

执行阶段只接受绑定当前冻结剪辑规格的编译工程和成功 RenderJob。成片检查由服务端派生验收预期并生成 HMAC 检查绑定；最终 `ExecutionManifest` 引用该 RenderJob、编译快照、成片、检查报告与检查绑定，提交时逐项重验路径、哈希和报告结论。

原创任务的前三个阶段均检索共享知识：

| 创作阶段 | 检索范围 | 产物边界 |
| :-- | :-- | :-- |
| 阶段一：总体方案 | 视频类型、核心机制、视觉语言、节奏方法、观看体验 | 只表达语义方向，不包含素材路径、时间点、坐标、镜头数量或引擎参数 |
| 阶段二：素材与 BGM | 素材选择、预处理、音乐结构、能量和节奏特征 | 冻结实际资源及溯源，不设计最终时间线 |
| 阶段三：剪辑规格 | 剪辑句子、图层模式、音画关系、密度与转场规律 | 只使用阶段二冻结资源，生成逐镜表和严格 ActionSpec |

每次检索写入独立审计记录，包含查询、当前 StageRun、命中 Knowledge ID、Publication ID、结果哈希和嵌入版本。阶段主产物必须引用属于本任务当前阶段 revision 且命中共享知识的 `retrieval_id`。

### 参考驱动创作

参考报告在同一任务中确认后进入原创流程。创作阶段先调用 `reference_get_creation_context` 取得本任务冻结的参考 Artifact、FreezeRecord、当前阶段投影及哈希，再检索其他 active 共享知识；本次参考分析不依赖向量召回才能进入上下文。三个阶段产物都携带服务端返回的 `ReferenceContextBinding`，提交时重新校验。原创任务不携带该字段，但阶段一、二、三均保留共享知识检索能力。

## 知识存储

知识系统包含：

- SQLite：任务、阶段、Artifact、FreezeRecord、Publication 和检索审计。
- 内容寻址对象库：JSON、Markdown、帧、音频、报告和工程文件。
- LanceDB：`creation_knowledge` 与 `reference_evidence` 两个隔离集合。

创作检索强制满足：

```text
publication status = active
visibility = creation_shared
transferability = reusable_mechanism
applicable_stages = 当前阶段
knowledge_type = 查询声明类型
```

原片人物、物象、具体时间点和效果参数保留在 `reference_evidence`，不进入共享创作召回。同一源媒体的新 Publication revision 会 supersede 旧 active revision；旧记录继续保留审计状态。

## MCP 能力

### 工作流与上下文

- Context Catalog、rules、skills 和 Schema Resources。
- Task、StageEnvelope、Artifact、确认冻结、阶段重开。
- 受句柄保护的 Artifact 与 Evidence Resources。

### 参考分析与报告

- 显式视频下载、来源解析、媒体探测。
- 视频和音频多遍分析、密集区间复核、产物校验。
- 参考报告 JSON 与中文 Markdown 生成。
- 知识发布预览、发布和带审计的阶段检索。

### 资源筹备

- 视频素材来源、搜索和取得。
- Wikimedia Commons 图片来源、搜索和取得。
- Mixkit BGM 来源、搜索、取得和逐素材权利记录。
- 视频裁切、音频裁切、抽帧和等比缩放补边预处理。

### 编辑与成片

- 工程创建、素材导入、CommandBatch 和 revision 控制。
- EditingSpecification 能力预检。
- ActionSpec 到 `EditorProject 2.0` 与 SpecTraceMap 的确定性编译。
- 工程与 TraceMap 覆盖校验、渲染提交、任务查询和成片检查。

## 产物目录

```text
output/plugin/
├── workflow.sqlite3
├── retrieval.sqlite3
├── objects/
├── tasks/{task_id}/
│   └── resources/
│       ├── images/
│       └── preprocessed/
├── knowledge/
│   ├── publications.sqlite3
│   └── knowledge.lancedb/
├── materials/
├── bgm/
└── editor/
```

所有媒体和阶段产物记录 SHA-256。取得类组件保存来源、作者、授权页面和派生关系；来源授权字段属于逐素材证据，项目发布判断在实际用途确定后完成。

## 当前剪辑引擎能力

确定性编译当前覆盖：

- 素材源区间裁切；
- 静态位置、尺寸、旋转和透明度；
- 多视觉轨叠层与固定样式文本；
- 静态音量与多路音频；
- H.264/AAC MP4 输出。

关键帧、缓动、变速、动画遮罩、转场对象和跨镜头 Composition 会形成 `CapabilityGap`，编译器不会静默替换或删减规格动作。
