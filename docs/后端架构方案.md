# 后端架构方案

## 组件边界

视频下载组件位于 `components/video_download/`，向 Agent 提供同步 Python API 和命令行入口。组件负责分享文本取链、平台下载、元数据命名和本地落盘，不负责视频分析、字幕提取、内容编辑或 HTTP 服务。

调用链固定为：

```text
Agent
  -> download_video / video-download
  -> URL 提取与平台识别
  -> Douyin Playwright 链路 或 yt-dlp 通用链路
  -> 元数据命名
  -> {output_dir}
```

## 外部依赖

| 依赖 | 边界 |
| :-- | :-- |
| 视频平台页面、详情接口与媒体 CDN | 视频来源和媒体传输；可用性受平台访问策略影响 |
| yt-dlp | 通用平台元数据解析、媒体选择和音视频合并调度 |
| Playwright Chromium | 抖音页面执行和详情响应拦截 |
| httpx | 抖音媒体直链流式下载 |
| FFmpeg | yt-dlp 音视频分流合并 |

组件不持有平台账号。Cookie 文件、代理和浏览器 CDP 地址由调用方显式提供，配置只在当前下载调用中使用。

## 数据边界

- 输入：纯 HTTP(S) URL 或包含 URL 的平台分享文本。
- 运行时临时文件：`{output_dir}/.video-download-*`，成功后改为最终名称，失败时清理。
- 最终文件：`{output_dir}/{UTC时间戳}_{摘要}_{视频ID}.{ext}`；`output_dir` 默认为 `output/download`。
- 命令输出：下载调用的成功和失败 JSON 写入标准输出，进度写入标准错误；`--help` 输出命令帮助。
- 已有同名文件不覆盖，组件原子占用新名称并追加数字后缀。

## 素材获取组件

素材获取组件位于 `components/material_acquisition/`。`StockEngine` 统一八个素材源适配器；`MaterialAcquisitionService` 向 Agent 提供受约束的 `sources -> search -> acquire` 接口。

调用链固定为：

```text
Agent
  -> material-acquisition / MaterialAcquisitionService
  -> 已注册素材源关键词搜索
  -> 私有搜索记录 + 公开 candidate_ref
  -> 授权与来源字段校验
  -> 对应素材源下载到临时目录
  -> ffprobe 视频流验证
  -> downloads 文件 + provenance JSON
```

Agent 不能提交任意下载 URL，也不直接调用一步式搜索下载接口。平台分享链接仍由视频下载组件负责。素材画面语义检查、最终选定和剪辑规划位于下游流程。

### 外部依赖

| 依赖 | 边界 |
| :-- | :-- |
| Pexels、Pixabay、Archive.org | Agent 默认素材来源；前两者按环境变量配置 Key |
| 其他已抽取素材源 | `StockEngine` 低层扩展来源，不进入 Agent 默认链，接入时单独验证远端契约与逐素材授权字段 |
| httpx | 素材搜索和媒体流传输 |
| Pydantic | 跨来源候选和过滤条件模型 |
| Beautiful Soup | HTML 型低层素材源解析 |
| Playwright Chromium | Pond5 低层适配器的浏览器会话 |
| ffprobe | 获取阶段的视频流和媒体参数验证 |

### 数据边界

- 输入：内容关键词、过滤条件、已注册来源名，或搜索产生的 `candidate_ref`。
- 私有搜索记录：`{output_dir}/searches/search_<token>.json`。
- 临时下载目录：`{output_dir}/.material-acquisition-*`，获取结束后清理。
- 下载文件：`{output_dir}/downloads/<provider>_<provider_asset_id>.<ext>`。
- 溯源记录：`{output_dir}/provenance/<provider>_<provider_asset_id>.json`。
- 默认 `output_dir` 为 `output/materials`；同名文件追加数字后缀，不覆盖已有文件。
- 成功和失败 JSON 写入标准输出，进度写入标准错误；`--help` 输出命令帮助。

## 本地视频剪辑器组件

本地视频剪辑器位于 `components/video_editor/`。浏览器、Python、CLI 与 HTTP 入口共享领域命令服务；工程持久化、素材探测、FFmpeg 编译、FFmpeg 进程和任务队列保持独立边界。

```text
浏览器 / Python / CLI / HTTP
          -> VideoEditorService
          -> ProjectStorage

素材入口 -> media -> ffprobe
导出入口 -> PersistentRenderQueue
         -> RenderPlan
         -> FFmpegRenderer -> ffmpeg -> ffprobe
```

### 代码边界

| 模块 | 职责 |
| :-- | :-- |
| `models.py`、`commands.py` | `EditorProject`、命令批次与严格校验 |
| `service.py` | 服务生成 ID、命令执行、引用校验与 revision 语义 |
| `storage.py` | 工程目录、写锁与原子 `project.json` |
| `media.py` | 素材分块落盘、路径边界与 ffprobe 元数据 |
| `render.py` | 纯 `RenderPlan` 编译、FFmpeg 进程、验证与原子发布 |
| `jobs.py` | 持久化单并发队列、取消、重启恢复与跨进程 worker 独占 |
| `api.py`、`__main__.py` | HTTP 与 Agent CLI 薄适配 |
| `web/` | 原生 HTML、CSS、ES Modules 工作台与浏览器组合预览 |

`VideoEditorService` 不引用 Web 或 FFmpeg 模块。浏览器拖动只更新声明式工程和本地媒体预览，FFmpeg 只在导出任务中运行。

工程协议使用 `schema_version: "2.0"`。`Track.media_domain` 只保留 `visual` 或 `audio` 处理域；`Clip.kind` 使用 `media` 或 `text` 表达内容。visual 轨接受视频、图片和文本片段，audio 轨接受音频片段。主画面、画中画、字幕和配乐是轨道名称或片段用途，不形成专用轨道类型。

轨道通过 `track.add`、`track.update`、`track.move` 和 `track.delete` 动态管理。`tracks` 数组按网页从上到下排列；在所有 visual 轨中，数组位置更靠前者层级更高，第一条 visual 轨是最高视觉层，audio 轨的位置不参与视觉合成。渲染编译器反向遍历并跳过 audio 轨，保证底层先合成、顶层后合成。轨道规则集中在模型与服务层，网页和渲染器只适配同一顺序语义。

### 外部依赖

| 依赖 | 边界 |
| :-- | :-- |
| FastAPI、Starlette、Uvicorn | 本机 HTTP API、静态界面、上传与 Range 文件响应 |
| Pydantic | 工程、命令、任务与 API 请求边界 |
| python-multipart | 浏览器素材上传 |
| FFmpeg | 画布、裁剪、图层、文字、混音与 H.264/AAC 编码 |
| ffprobe | 素材探测与导出结果验证 |

### 数据与容错边界

- 工程：`output/editor/projects/{project_id}/project.json`。
- 素材：`output/editor/projects/{project_id}/assets/`。
- 导出：`output/editor/projects/{project_id}/renders/`。
- 任务：`output/editor/render_jobs/{render_job_id}/`，包含任务、请求和工程快照。
- 写命令携带 `expected_revision`；过期写入返回 `revision_conflict`。
- 工程先写临时 JSON 再同目录替换；超过 60 秒的陈旧写锁在下一次写入时回收。
- 导出先写临时 MP4，经 ffprobe 验证后替换目标；失败保留已有成品。
- 服务重启后恢复排队任务；中断的运行任务记录为失败并保存 `render_interrupted`。
- 同一任务根目录的渲染 worker 跨进程独占，单次只执行一个 FFmpeg。
- 单次 FFmpeg 默认总执行时限为 3600 秒；超时任务记录 `render_timeout`，终止进程后继续消费队列。
