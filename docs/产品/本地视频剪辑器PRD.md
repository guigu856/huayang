## 第一章：产品概述

本地视频剪辑器是一款面向视频创作者与自动化 Agent 的本地网页视频编辑组件，让用户和 Agent 能够围绕同一份工程完成可视化剪辑与程序化剪辑，而无需在多个私有工程格式之间搬运时间线。

### 1.1 差异化对比表

以下内容是对“剪映类成熟编辑器”产品形态的结构性推断，未核验其当前全部能力，不作为竞品现状声明。

| 功能 | 竞品 | 本产品 | 实现方式 |
| :-- | :-- | :-- | :-- |
| Agent 直接编辑工程 | 人工作业界面通常是核心入口，此处未验证其公开命令协议 | Agent 与网页拥有同等编辑能力 | 统一命令模型、稳定错误码、Python API、CLI 与 HTTP 适配器 |
| 工程可审计 | 专有工程内部结构通常不作为稳定公开契约，此处未验证具体格式 | 工程文件可读、可比较、可生成 | 带 `schema_version: "2.0"` 与 `revision` 的声明式 JSON，素材使用相对引用 |
| 预览与导出一致性 | 成熟编辑器内部引擎实现未公开 | 同一时间语义、层级语义和变换语义贯穿两端 | 共享场景计划器，浏览器预览适配器与 FFmpeg 导出适配器只负责执行 |
| 本地数据边界 | 云能力与账号体系通常占据产品链路的一部分，此处未验证离线覆盖范围 | 默认不联网、不注册、不上传工程与媒体 | 服务仅绑定回环地址，工作区与缓存均落在用户指定目录 |
| 自动化失败定位 | UI 自动化通常只能从界面状态推测失败点 | 每次修改均返回机器可读证据 | 命令批次返回更新后的工程与 revision，失败返回稳定错误码 |

### 1.2 三类用户画像

| 角色 | 核心目标 | 对现有工具最大的不满 | 让其切换的一个功能 |
| :-- | :-- | :-- | :-- |
| 独立视频创作者 | 在本地完成常用多轨剪辑并稳定导出 | 自动化脚本与手工工程彼此割裂 | 网页中看到 Agent 改动后的同一条时间线 |
| Codex、Claude Code、Cursor 等编程 Agent 的操作者 | 用结构化命令批量完成可重复剪辑 | UI 坐标自动化脆弱且缺少结果契约 | 通过 Python、CLI 或 HTTP 发送同语义命令并获得回执 |
| 视频系统组件开发者 | 将剪辑能力嵌入更大的生成与制作流程 | 编辑器通常是封闭终端，难以组合和测试 | 可版本化工程模型、能力查询与稳定组件边界 |

### 1.3 可行性边界

| 在范围内（及原因） | 明确排除在外（及原因） |
| :-- | :-- |
| Windows 本机启动服务，在桌面浏览器打开单页编辑器；符合现有 Python 组件项目形态 | 手机端触控编辑；首版布局、文件访问与性能目标均针对桌面浏览器 |
| 导入本地视频、图片、音频并通过 ffprobe 建立元数据 | 从第三方平台抓取素材；已有下载与素材获取组件负责该边界 |
| 可增删、改名和重排的 visual/audio 多轨时间线；媒体与文本由片段类型表达 | 模板商城、云素材库、账号同步、团队协作和在线发布 |
| 拖放排序与定位、入出点裁剪、播放头分割、文本、画中画、位置、缩放、不透明度 | 智能字幕、抠像、美颜、复杂调色、曲线关键帧、转场和插件市场 |

| H.264 视频与 AAC 音频的 MP4 输出 | 专业中间编码、HDR、色彩管理、多声道混音和逐帧特效合成 |
| 单用户、单机、多工程文件，工程级写锁 | 多用户实时协同与跨机器分布式渲染 |
| Codex 等 Agent 通过本地 Python、CLI、HTTP 调用 | 为每一种 Agent 编写专属插件；稳定协议已经覆盖通用接入 |

### 1.4 约束分层

| 硬约束 | 推荐默认 | 发挥空间 |
| :-- | :-- | :-- |
| 一个工程模型承载网页、Python、CLI、HTTP 与导出；所有编辑命令先通过领域校验；写入采用原子替换；不覆盖源素材；服务默认只绑定 `127.0.0.1`；错误响应可机读；导出文件先写临时路径再提交 | 工程画布为 1920×1080、30 fps；时间单位为整数微秒；同一工程写命令串行；HTTP 使用 JSON；前端以命令回执更新状态；缓存可重建 | 网页配色、面板细节、时间线缩略图样式、空状态、拖动吸附提示、进度动画和无障碍增强 |

```text
| | 音频 1           | | +-------------------------------------------+ | | 缩放 0.80           | |
| | 城市夜景.mp4     | | | 播放  00:12.400 / 00:42.000  音量       | | | 不透明度 100%       | |
| +------------------+ | +-------------------------------------------+ | +---------------------+ |
+----------------------+-----------------------------------------------+-------------------------+
```

```text
活动状态：城市夜景.mp4 正在探测 63%
错误状态：采访.mov 读取失败 → 查看详情 / 移除
```

#### b) 交互流程

```text
点击“导入本地素材” --> 选择一个或多个文件 --> 复制或引用到工程素材区
    |
    +-- ffprobe 成功 --> 写入媒体元数据 --> 生成缩略图或波形任务 --> 素材可拖入时间线
    |
    +-- 格式不支持 --> 保留源文件不变 --> 显示 unsupported_media --> 可移除失败项
    |
    +-- 文件读取失败 --> 不写入素材记录 --> 显示 asset_unreadable --> 重新选择文件
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
| :-- | :-- | :-- | :-- |
| 空 | 工程没有素材 | 导入说明与主按钮 | 成功导入首个素材 |
| 探测中 | 已选文件等待 ffprobe | 素材行进度与禁用拖动 | 探测成功或失败 |
| 可用 | 元数据完整且源文件存在 | 缩略图、类型、时长 | 文件丢失或被移除 |
| 缓存生成中 | 缩略图或波形任务运行 | 非阻塞小型进度标识 | 缓存成功或失败 |
| 缺失 | 工程引用的源文件不存在 | 红色“源文件缺失” | 用户重新定位或移除 |
| 失败 | 探测或读取失败 | 错误码与查看详情 | 重试成功或移除 |

#### d) 依赖关系

读取文件选择结果与工程工作区；调用媒体探测端口；写入 `Asset` 和工程 revision。素材库只产生素材引用，不创建时间线片段；时间线通过 `asset_id` 读取素材。

#### e) 待决问题

- 此处未解决：首版导入默认复制素材到工程，还是仅保存相对路径。安全默认是复制到工程的 `assets` 目录，避免外部文件移动后失效。
- 此处未解决：首版支持的输入容器集合。默认以本机 FFmpeg 与 ffprobe 实际探测结果为准，导入前通过能力查询返回支持情况。


#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
| :-- | :-- | :-- | :-- |
| 无内容 | 当前时间无可见片段 | 黑色画布与引导文案 | 播放头进入片段范围 |
| 暂停 | 工程已加载且未播放 | 静止画面与播放按钮 | 点击播放或移动播放头 |
| 播放 | 时钟正在推进 | 暂停按钮与运行时间码 | 暂停、到结尾或发生阻断错误 |
| 跳转 | 用户拖动播放头 | 低成本帧预览与等待标识 | 目标帧显示 |
| 局部降级 | 某一层解码失败 | 该层显示素材名占位块 | 重试成功、重新定位或移除片段 |
| 阻断错误 | 主视频源缺失或浏览器不支持解码 | 画布错误卡片 | 修复素材或切换工程 |

#### d) 依赖关系

读取工程快照、选择状态、播放时钟和缓存；读取媒体流端点；不写工程。播放头位置属于界面会话状态，只有用户执行剪辑命令时才产生工程写入。

#### e) 待决问题

- 此处未解决：目标机器浏览器对源素材编码的覆盖率。默认对浏览器不支持但 FFmpeg 可读的素材显示预览降级提示，后续再引入代理文件。
- 此处未解决：文本字体跨机器一致性。默认使用首版固定字号、颜色与渲染器字体策略，并在视觉一致性测试中记录差异。

#### b) 交互流程

```text
从素材库拖动素材 --> 选择目标轨道和开始时间 --> 发送 clip.add 命令
    |
    +-- 校验通过 --> revision 增加 --> 时间线按服务端快照更新 --> 自动保存完成
    |
    +-- 轨道处理域不匹配 --> 命令不落盘 --> 显示 track_domain_mismatch --> 保留拖动前状态
    |
    +-- revision 冲突 --> 拉取最新工程 --> 保留当前选择 --> 提示重做本次拖动

    |
    +-- 入出点合法 --> 更新两个片段或片段边界
    |
    +-- 越过素材边界 --> 返回 source_range_invalid --> 恢复到命令前位置
```

#### c) 状态清单

| 名称 | 触发条件 | 视觉标识 | 退出条件 |
| :-- | :-- | :-- | :-- |
| 空 | 没有轨道或片段 | 投放区与添加文本入口 | 插入首个片段 |
| 就绪 | 工程快照加载完成 | 轨道、刻度与播放头 | 开始拖动或命令执行 |
| 选中 | 单击片段 | 描边、控制点与属性联动 | 选择其他对象或空白处 |
| 拖动 | pointer 按下且越过阈值 | 半透明片段与目标时间 | 松开、取消或校验失败 |
| 裁剪 | 拖动片段左右边缘 | 入出点时间提示 | 松开、取消或校验失败 |
| 命令提交中 | 写命令已发送 | 片段锁定与顶部保存状态 | 收到回执或网络错误 |
| 冲突 | `expected_revision` 过期 | 冲突提示与刷新动作 | 拉取最新快照 |

#### d) 依赖关系

读取素材时长、轨道处理域、工程快照和当前 revision；向命令总线写入片段插入、移动、裁剪、分割、删除，以及轨道新增、改名、重排和删除命令。它不直接修改前端本地工程对象，不调用 FFmpeg。

#### e) 待决问题

- 同一 visual 轨允许片段时间重叠；同轨片段数组靠后的元素位于上层。跨轨重叠按 visual 轨在 tracks 数组中的相对顺序合成，位置更靠前者层级更高；audio 轨的位置不参与视觉层级。
- 此处未解决：拖动吸附精度。默认吸附到播放头、相邻片段边界和帧边界，按住 Alt 暂时关闭吸附。

#### c) 状态清单

#### d) 依赖关系

读取当前选择、画布尺寸、片段类型与工程 revision；通过 `clip.update` 写入片段的 `transform` 或 `text`。新增 visual 素材的初始 Transform 与轨道层级解耦，统一按主视频规则居中等比适配画布。用户可在属性面板输入几何数值，也可在预览画布拖动选框或四角等比缩放；预览手势结束时提交一次完整 Transform。画中画使用上层 visual 轨的视频或图片片段，以显式的 `x`、`y`、`width`、`height` 和 `opacity` 表达。

#### e) 待决问题

- 此处未解决：首版字体选择器是否扫描全部系统字体。默认只提供固定常用字体与工程字体，避免系统扫描阻塞启动。
- 此处未解决：属性面板的缩放控件是否允许打破原始宽高比。默认等比更新 `width` 与 `height`，工程仍保存显式像素尺寸。

## 第四章：超越竞品的差异化功能

### 第 4.1 节 同工程、同命令、四入口

1. **竞品为何没有这个功能**：基于公开产品形态的推断，成熟消费级编辑器主要优化人工作业与内部工程兼容，公开且稳定的可写工程协议会增加兼容承诺和测试成本；具体竞品当前接口能力未验证。
2. **本产品如何实现**：领域命令与工程仓库位于 Python 核心层。网页通过 HTTP、CLI 通过参数或标准输入、Python 调用方通过方法调用进入相同服务。适配器只处理传输与序列化。
3. **交互流程**：

```text
网页操作 ----+
Python API --+--> VideoEditorService --> 命令批次校验 --> 原子工程保存 --> 新 revision
CLI ---------+
HTTP --------+
```

4. **风险与应对**：适配器可能引入字段差异。契约测试对四个入口执行同一命令样例，并比较工程快照与错误码；任何入口不得拥有额外领域分支。

### 第 4.2 节 revision 控制的原子命令批次

1. **竞品为何没有这个功能**：基于产品入口差异的推断，人工作业界面以视觉结果作为反馈，通常没有面向外部 Agent 的乐观并发契约；具体竞品自动化协议未验证。
2. **本产品如何实现**：每个 `CommandBatch` 带 `expected_revision` 和一个或多个带 `type` 的命令。批内命令先应用到内存副本，全部成功后 revision 只增加 1 并原子保存；失败响应包含稳定错误码与结构化 details。
3. **交互流程**：

```text
Agent 读取工程 --> 生成 CommandBatch --> 读取响应
                                      |
                                      +-- ok --> 保存返回工程的新 revision --> 继续下一步
                                      |
                                      +-- invalid_input --> 修正批次结构 --> 重新提交
                                      |
                                      +-- revision_conflict --> 读取 actual_revision 对应快照 --> 重新规划
```

4. **风险与应对**：调用方在收到响应前断开时，结果状态可能不明确。调用方先重新读取工程；revision 已增加时依据工程快照判断结果，revision 未变化时才重新提交。首版不声明跨请求幂等键。

### 第 4.3 节 可定位的持久化渲染任务

1. **竞品为何没有这个功能**：基于封闭运行环境的推断，消费级桌面编辑器通常以界面进度为主要反馈；本产品面向外部 Agent，需要在进程重启后仍能查询任务结果。竞品具体任务协议未验证。
2. **本产品如何实现**：`POST /api/v1/projects/{project_id}/renders` 在入队前核对 expected_revision、工程可渲染性、素材路径和输出目录；队列工作线程使用 `compile_render_plan` 生成可检查的 `RenderPlan`。任务失败时保存稳定错误码与 FFmpeg 摘要。
3. **交互流程**：

```text
点击导出 --> 核对工程 revision 与素材 --> 创建持久化渲染任务
    |
    +-- 校验通过 --> 进入单并发队列 --> FFmpeg 导出
    |
    +-- 工程或素材问题 --> 返回结构化错误 --> 定位片段或素材后重试
    |
    +-- FFmpeg 缺失 --> 任务失败并显示 `ffmpeg_unavailable` --> 保持工程可编辑
```

4. **风险与应对**：编解码失败可能只在 FFmpeg 运行时出现。临时 MP4 保持在任务目录，ffprobe 验证通过后才发布成品；失败任务保留错误摘要并清理临时输出。

### 超预期机会

- 在网页的 Agent 接口面板中显示“上一条命令改变了什么”，点击即可定位受影响片段。
- 渲染任务的错误项可直接跳到对应轨道、片段或素材。
- 工程 JSON 提供稳定排序和规范化输出，使 Git diff 可读并减少无意义变更。

## 第五章：数据模型

工程文件使用 JSONC 说明，实际落盘为标准 JSON。时间统一使用浮点秒，网页显示到毫秒，所有引用使用稳定 ID。工程的版本概念（`"version"`）统一由 `schema_version` 表达，不设置第二个版本字段。

### 5.1 工程

```jsonc
{
  "schema_version": "2.0", // 必填；工程 Schema 版本，默认值: 2.0
  "id": "project_92f53b6789abcdef", // 必填；project_ 加 16 位小写十六进制字符
  "name": "城市漫游", // 必填；1 到 200 个 Unicode 字符
  "revision": 18, // 必填；每次成功命令批次加 1，默认值: 0
  "canvas": { // 必填；输出画布
    "width": 1920, // 必填；像素宽度，范围 1 到 7680
    "height": 1080, // 必填；像素高度，范围 1 到 7680
    "fps": 30, // 必填；帧率，大于 0 且不超过 240
    "background_color": "#000000" // 必填；十六进制颜色，默认值: #000000
  },
  "assets": [], // 必填；Asset 对象集合，默认值: 空集合
  "tracks": [] // 必填；Track 对象集合，按网页从上到下排列；第一条 visual 轨为最高视觉层
}
```

### 5.2 素材

```jsonc
{
  "id": "asset_92f53b6789abcdef", // 必填；工程内稳定唯一标识
  "kind": "video", // 必填；video、image、audio 之一
  "name": "city-night.mp4", // 必填；1 到 200 个 Unicode 字符
  "path": "assets/city-night.mp4", // 必填；相对工程目录的规范路径
  "metadata": { // 必填；ffprobe 规范化媒体元数据
    "duration": 18.2, // 视频和音频必填；单位秒，大于 0
    "width": 1920, // 视频和图片必填；正整数像素
    "height": 1080, // 视频和图片必填；正整数像素
    "frame_rate": 30, // 视频可选；大于 0
    "video_codec": "h264", // 视频可选；探测到的编码名
    "audio_codec": "aac", // 音频流可选；探测到的编码名
    "sample_rate": 48000, // 音频流可选；正整数 Hz
    "channels": 2 // 音频流可选；正整数声道数
  }
}
```

### 5.3 轨道与片段

```jsonc
{
  "id": "track_92f53b6789abcdef", // 必填；工程内稳定唯一标识
  "media_domain": "visual", // 必填；visual、audio 之一
  "name": "主画面", // 必填；1 到 200 个 Unicode 字符
  "clips": [] // 必填；Clip 对象集合
}
```

```jsonc
{
  "id": "clip_92f53b6789abcdef", // 必填；工程内稳定唯一标识
  "kind": "media", // 必填；media、text 之一

    "height": 270, // 必填；输出像素高度，大于 0，默认值: 1080
```

### 5.4 Agent 命令批次与响应

```jsonc
{
  "expected_revision": 18, // 必填；调用方基于的工程 revision
  "commands": [] // 必填；至少一个带 type 判别字段的命令，此处以空集合展示容器形态
}
```

```jsonc
{
  "ok": false, // 必填；请求是否成功
  "error": { // 失败时必填；成功时改为 data 字段
    "code": "revision_conflict", // 必填；稳定机器错误码
    "message": "工程已被其他写入者更新", // 必填；中文说明
    "details": { // 必填；结构化上下文，默认值: 空对象
      "expected_revision": 18, // 冲突时必填；请求 revision
      "actual_revision": 19 // 冲突时必填；当前 revision
    }
  }
}
```

命令元素使用点号命名的 `type`，包括 `project.update`、`asset.add`、`asset.delete`、`track.add`、`track.update`、`track.move`、`track.delete`、`clip.add`、`clip.update`、`clip.delete` 和 `clip.split`。`track.add` 接收 `media_domain`、`name` 和可选 `index`；`track.update` 修改名称；`track.move.to_index` 调整顺序。visual 轨接受视频、图片与文本片段，audio 轨接受音频片段；`Clip.kind` 决定使用 `asset_id` 还是 `text`。工程以素材、轨道和片段的稳定 ID 建立引用。缓存、播放头、选中项、渲染进度和绝对素材路径不进入工程 JSON；渲染任务状态存放在工程旁的独立目录。

## 第六章：技术架构

```text
+--------------------------------------------------------------------------------+
| 接入层：网页、Python API、CLI、HTTP；只负责输入输出、认证边界和协议映射        |
+----------------------------------------+---------------------------------------+
                                         |
                                         v
+--------------------------------------------------------------------------------+
| 服务层：VideoEditorService；执行 CommandBatch、领域校验、revision 与结果       |
+----------------------------------------+---------------------------------------+
                                         |
                                         v
+--------------------------------------------------------------------------------+
| 模型层：EditorProject、Asset、Track、Clip、Transform、CommandBatch             |
+--------------------+-------------------+--------------------+------------------+
                     |                   |                    |
                     v                   v                    v
+--------------------------+ +----------------------+ +---------------------------+
| ProjectStorage           | | media.py             | | RenderPlan 与持久化任务    |
| 工程 JSON、文件锁、原子写| | 导入、路径、ffprobe  | | FFmpeg、进度、输出验证     |
+-------------+------------+ +----------+-----------+ +-------------+-------------+
              |                         |                           |
              v                         v                           v
+--------------------------------------------------------------------------------+
| 基础设施层：本地文件系统、原子 JSON、子进程、HTTP Range 媒体流、静态网页资源   |
```

| 库名 | 用途 | 为何优于替代方案 | 大致包体积 |
| :-- | :-- | :-- | :-- |
| Pydantic | 工程、命令与回执 Schema 校验 | 项目已使用，Python 类型与 JSON Schema 可从同一模型产生 | 未知 |
| FastAPI | 本地 HTTP API、OpenAPI 与静态入口 | 与 Pydantic 直接协作，路由层保持薄适配 | 未知 |
| Uvicorn | 本地 ASGI 进程 | 启动入口简单，适合单机长连接与进度事件 | 未知 |
| 浏览器原生 HTML、CSS 与 ES Modules | 编辑器界面、模块划分与状态更新 | 没有 Node 构建链和前端框架运行时，适合首版单机组件 | 额外运行时 0 字节 |
| FFmpeg | 真实视频、音频合成与 MP4 编码 | 覆盖时间裁剪、叠加、文字与混音所需滤镜 | 系统可执行文件，大小未知 |
| ffprobe | 媒体元数据与输出验证 | 与 FFmpeg 能力语义一致，可输出机器可读 JSON | 随 FFmpeg 分发，大小未知 |

最大架构风险是浏览器预览与 FFmpeg 输出产生语义漂移。`EditorProject` 是两端的共同语义：浏览器把 `timeline_start`、`duration`、`source_in` 和 `Transform` 映射为 DOM 媒体层，`compile_render_plan` 把同一字段映射为 `RenderPlan`。固定工程夹具在指定时间点生成预览截图与导出帧，验证几何位置、可见层和时间边界。

### 可替换技术原则

推荐原生 HTML、CSS、ES Modules、FastAPI 与 FFmpeg。网页技术可在保持 HTTP 契约和界面行为时替换；服务框架可在保持 `VideoEditorService` 边界时替换；渲染器可在保持工程字段语义时增加适配器。不可变项是 `EditorProject`、`CommandBatch`、revision、稳定错误码、原子持久化与可验证 MP4 输出。

## 第八章：导出与输出系统

### 8.1 支持的输出格式

| 格式 | 使用场景 | 质量选项 | 备注 |
| :-- | :-- | :-- | :-- |
| MP4，H.264 与 AAC | 最终播放文件 | 画布分辨率、fps、CRF 18、23、28 | 首版唯一视频输出；完成后必须通过 ffprobe 验证 |
| 标准 JSON 工程 | 保存、复制、Agent 编辑、版本比较 | 规范化缩进与稳定字段顺序 | 含相对素材引用，不含缓存、播放头与选择状态 |
| JSON 命令回执 | Agent 自动化证据与故障判断 | 单条或原子批回执 | 含命令 ID、revision、结果或稳定错误码 |
| JSON 任务记录 | 导出进度、日志索引与取消结果 | 每个导出任务一份 | 进程重启后可读取最终状态，运行中任务标记为 interrupted |

### 8.2 输出文件结构

```text
output/editor/
+-- projects/
|   +-- project_92f53b6789abcdef/
|       +-- project.json
|       +-- .project.lock
|       +-- assets/
|       |   +-- city-night.mp4
|       |   +-- cafe-closeup.mp4
|       |   +-- city-ambience.wav
|       |   +-- corner-logo.png
|       +-- renders/
|           +-- render_92f53b6789abcdef.mp4
+-- render_jobs/
    +-- .worker.lock
    +-- render_92f53b6789abcdef/
        +-- job.json
        +-- project.json
        +-- request.json
```

### 8.3 批量处理流程

```text
收到多个导出请求
    |
    v
解析工程与入队校验  -- 最多 2 个并行
    |
    +-- 失败 --> 单独返回问题清单，不进入渲染队列
    |
    +-- 通过 --> 固化各自 revision 快照
                    |
                    v
              FFmpeg 渲染队列  -- 默认仅 1 个运行
                    |
                    v
              ffprobe 输出验证 -- 与下一个工程入队校验可并行
                    |
                    +-- 成功 --> 原子提交 MP4 与任务记录
                    +-- 失败 --> 清理临时文件并保存日志
```

同一工程的命令批次先在内存副本上依次校验，全部成功后只增加一次 revision 并原子保存；任一命令失败时整批保持原工程。多个工程的入队校验可并行。渲染队列与任务状态持久化，CPU 密集的编码固定为单并发；进程重启后，queued 任务继续排队，原 running 任务转为 failed 并记录 `render_interrupted`。

## 第十一章：开发者交接说明

### a) 实现顺序建议

你先实现 `EditorProject`、`CommandBatch`、`VideoEditorService` 和契约测试，锁定浮点秒、轨道、片段、Transform 和 revision 语义。随后实现 `ProjectStorage`、Python API、CLI 与 HTTP 薄适配器。第三步实现原生网页工作台、多轨时间线和 DOM 媒体组合预览。最后实现纯 `RenderPlan` 编译、持久化单并发任务、FFmpeg 渲染、ffprobe 验证和完整端到端夹具。

### b) 最可能导致返工的三个决策

1. **时间表示**：安全默认是整数微秒，所有裁剪与分割在领域层对齐到工程帧边界。若真实素材存在可变帧率且逐帧定位误差超过一帧，需要引入源时间基映射，但工程外部契约仍保持整数时间。
2. **预览与导出语义**：安全默认是浏览器预览与 `compile_render_plan` 直接映射同一 `EditorProject` 字段。若视觉回归显示位置或尺寸差异超过 2 像素，先统一坐标与旋转规则，再调整各端执行细节。
3. **素材路径策略**：安全默认是导入时复制到工程 `assets` 目录并保存相对路径。若用户样本中超大素材复制时间普遍超过 30 秒，需要增加受控外部引用模式，并保留哈希、缺失检测与重新定位契约。

### c) 哪里要严格，哪里可以灵活

| 范围 | 属性 | 说明 |
| :-- | :-- | :-- |
| 第一章的边界与约束分层 | 约束 | 你不得扩入账号、云同步、移动端或智能生成能力 |
| 第三章的命令行为与失败原子性 | 约束 | 网页与 Agent 必须得到相同结果，失败不得产生半个工程 |
| 第五章的 ID、时间、schema_version、revision 与引用方向 | 约束 | 它们是跨入口和后续组件的持久契约 |
| 第六章的分层与端口方向 | 约束 | 领域层与 HTTP、网页、文件系统和 FFmpeg 保持单向端口关系 |
| 第八章的临时文件、验证与原子提交 | 约束 | 已有输出和源素材不得被失败任务覆盖 |
| 第二章的面板视觉比例 | 建议 | 你可根据真实可用空间微调，但四个核心区域必须在桌面首屏可达 |
| 第七章的样式、文案与微交互 | 建议 | 你可优化可读性与操作反馈，不改变命令含义 |
| 第六章列出的可替换库 | 建议 | 你可沿用仓库已存在的等价技术，保持不可变协议 |

### d) 已知的未知项

- 此处未解决：目标用户机器上的 FFmpeg 具体构建、编码器和字体集合。渲染任务必须把依赖差异变成稳定错误码与结构化 details。
- 此处未解决：真实项目的典型素材编码、分辨率、总时长和轨道规模。先以第十章夹具建立基线，再用用户项目记录峰值。
- 此处未解决：浏览器对输入视频编码的覆盖率。FFmpeg 可读但浏览器不可读时保持工程可导出，并给出预览降级证据。
- 此处未解决：Claude Code、Cursor 等调用方对 CLI 标准输入与本地 HTTP 的偏好。三种通用入口保持等价，后续只增加薄适配器。

### e) 验收剧本

**验收剧本 1：人类网页闭环。** 在 Windows 本机运行 `uv run video-editor serve --host 127.0.0.1 --port 8765`，用浏览器打开 `http://127.0.0.1:8765`，新建“城市漫游”工程，导入一个视频、一个图片和一个音频；新增 visual 轨并改名为“画中画”，新增 audio 轨后删除，再把轨道下移和上移；将三类素材拖入匹配处理域并保存。应看到轨道顺序、素材、时间线与预览一致，并用浏览器截图、`project.json` 和服务日志验证。

**验收剧本 2：核心剪辑。** 在网页选中主视频，将入点裁掉 1 秒，在 6 秒处分割，移动第二段到 8 秒，添加“城市漫游”文本，再把图片放到主画面上方的 visual 轨并设置为 480×270、X 为 1320、Y 为 80；应看到 revision 连续增长、图片位于主画面上层，刷新页面后布局保持，并用工程 JSON 与刷新前后截图验证。

**验收剧本 3：Agent 等价编辑。** 对同一初始夹具分别调用 Python API、CLI 和 HTTP 执行轨道新增、改名、重排、删除，以及片段新增、移动、裁剪、分割、文本与 Transform 命令；应得到相同稳定错误码与规范化工程快照，并用 `uv run pytest tests/test_video_editor_core.py tests/test_video_editor_api.py tests/test_video_editor_cli.py` 的输出验证。

**验收剧本 4：并发与故障恢复。** 同时提交两条基于同一 revision 的写命令，并放置一个超过 60 秒的 `.project.lock`；应只有一条并发命令提交，另一条返回冲突结果，陈旧锁可被回收，重新启动后 `project.json` 可读取且没有半写文件，并用目录扫描与 `uv run pytest tests/test_video_editor_core.py tests/test_video_editor_jobs.py` 验证。

**验收剧本 5：真实导出。** 使用项目测试夹具完成包含两条 visual 轨、一条 audio 轨，以及主视频、音频、文本和画中画的 10 秒工程，通过 `POST /api/v1/projects/{project_id}/renders` 创建任务并等待完成；应从 `/api/v1/render-jobs/{job_id}/output` 取得可播放 MP4，第一条 visual 轨位于最高层且 audio 轨移动不改变视觉层级，位置和分割时间与工程一致，并用 `uv run pytest tests/test_video_editor_render.py tests/test_video_editor_jobs.py`、ffprobe JSON 和指定时间点截图验证。
