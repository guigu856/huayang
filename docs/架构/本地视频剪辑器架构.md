# 本地视频剪辑器架构

> 本文定义 `components/video_editor/` 的最终边界、协议、故障处理和性能控制。产品行为以 `docs/产品/本地视频剪辑器PRD.md` 为准。

## 1. 系统目标

本地视频剪辑器是现有视频创作项目中的独立组件。网页用户与 Agent 共同读写一份 `schema_version: "2.0"` 的声明式工程，浏览器负责组合预览，FFmpeg 仅在导出任务中执行最终渲染。

```text
原生 HTML / CSS / ES Modules 网页 -----+
Python VideoEditorService -------------+--> 命令批次 --> EditorProject JSON
video-editor CLI ----------------------+                    |
FastAPI /api/v1 -----------------------+                    v
                                                    浏览器组合预览
                                                            |
                                                            v
                                                    持久化单并发队列
                                                            |
                                                            v
                                                    FFmpeg --> MP4
```

| 维度 | 架构规约 |
| :-- | :-- |
| 可扩展性 | 工程 Schema、带判别字段的命令联合类型、服务方法、HTTP 路由和渲染编译器是明确扩展点；接入层保持薄映射 |
| 可维护性 | Python 领域模型只有一份；网页按 API、状态、时间线、预览和工作台拆分 ES Modules；错误码集中管理 |
| 解耦 | `VideoEditorService` 不依赖 FastAPI、CLI、浏览器和 FFmpeg；`compile_render_plan` 只消费不可变工程快照；网页只调用 `/api/v1` |
| 容错 | 每个命令批次先在内存副本完成校验，再按 expected_revision 加锁并原子替换工程；渲染写临时文件，ffprobe 验证后发布成品 |
| 性能瓶颈 | 时间线 DOM、浏览器多媒体解码、完整 JSON 写入、FFmpeg 滤镜图和编码 CPU 分别设置预算；编码队列固定单并发 |

## 2. 运行边界

### 2.1 组件职责

- 创建、列出、读取和原子保存本地工程。
- 导入视频、图片和音频，使用 ffprobe 读取媒体元数据。
- 执行工程、素材、轨道和片段命令批次。
- 提供多轨时间线、播放头、浏览器媒体组合预览和属性编辑。
- 提供 Python、CLI 和 HTTP 三种 Agent 入口。
- 将指定工程 revision 固化为渲染任务，串行调用 FFmpeg。
- 使用 ffprobe 验证输出并提供下载接口。

### 2.2 相邻组件

| 组件 | 关系 |
| :-- | :-- |
| `components/video_download/` | 负责从平台链接下载视频；输出文件可作为编辑器导入源 |
| `components/material_acquisition/` | 负责检索和获取公共素材；下载文件可作为编辑器导入源 |
| 上游 Agent | 生成剪辑规划并调用 Python、CLI 或 HTTP 命令批次 |
| FFmpeg 与 ffprobe | 本机系统依赖；前者只供最终导出，后者供导入探测和成品验证 |

账号、云同步、在线发布、多人协作、移动端、智能字幕、复杂特效和远程渲染位于组件范围之外。

## 3. 代码结构与职责

```text

+-- service.py           命令编排、领域校验、revision 更新
+-- storage.py           单工程 JSON、排他锁、原子写入
+-- media.py             导入复制、路径边界、ffprobe 探测
+-- render.py            RenderPlan、FFmpeg 执行与输出验证
+-- jobs.py              持久化单并发渲染队列、取消与恢复
+-- api.py               FastAPI、统一响应、静态网页和媒体接口
+-- errors.py            稳定 VideoEditorError
+-- web/
    +-- index.html       工作台语义结构
    +-- styles.css       中文桌面编辑器布局
    +-- api.js           /api/v1 客户端与 ApiError
    +-- state.js         工程快照和纯界面会话状态
    +-- timeline.js      时间线 DOM、拖放、裁剪和播放头
    +-- preview.js       HTMLMediaElement 与文本层组合预览
    +-- app.js           工作台事件编排
```

依赖方向：

```text
web --> HTTP /api/v1
api.py --> service.py + media.py + jobs.py
__main__.py --> service.py + media.py + jobs.py
service.py --> models.py + commands.py + storage.py
storage.py --> models.py
render.py --> models.py + media.py
models.py / commands.py / errors.py --> Pydantic 与 Python 标准库
```

边界规则：

- 网页只保存 `project.id`、当前选择、播放头、缩放和播放状态等会话数据，工程写入统一提交命令批次。
- HTTP 与 CLI 只做解析、错误映射和结果序列化，不复制轨道与片段规则。
- `VideoEditorService.apply` 是工程写命令的唯一应用入口。
- `ProjectStorage` 只处理工程文件和 revision，不执行媒体探测和渲染。
- `compile_render_plan` 是纯编译步骤，不修改工程和素材。
- 缓存、任务进度、当前选择、播放头和绝对路径不进入工程 Schema。

## 4. 数据契约

### 4.1 EditorProject

```json
{
  "schema_version": "2.0",
  "id": "project_92f53b6789abcdef",
  "name": "城市漫游",
  "revision": 4,
  "canvas": {
    "width": 1920,
    "height": 1080,
    "fps": 30,
    "background_color": "#000000"
  },
  "assets": [],
  "tracks": []
}
```

核心字段：

| 对象 | 字段 | 语义 |
| :-- | :-- | :-- |
| Project | `schema_version` | 固定字符串 `2.0`；未知版本由读取边界拒绝 |
| Project | `id` | `project_` 加 16 位小写十六进制字符 |
| Project | `revision` | 非负整数；每个成功命令批次恰好增加 1 |
| Canvas | `width`、`height` | 1 到 7680 的整数像素 |
| Canvas | `fps` | 大于 0 且不超过 240 的浮点数 |
| Asset | `id`、`kind`、`name`、`path`、`metadata` | 素材身份、类型、工程相对路径和探测元数据 |
| Track | `id`、`media_domain`、`name`、`clips` | `media_domain` 为 visual 或 audio；名称只表达用途，不参与类型判断 |
| Clip | `id`、`kind`、`timeline_start`、`duration`、`source_in` | `kind` 为 media 或 text；时间单位为秒；开始与源入点非负，持续时间大于 0 |
| Clip | `asset_id` 或 `text` | media 片段必须且只能使用 asset_id，text 片段必须且只能使用 text |
| Clip | `transform`、`volume` | 视觉几何与不透明度；音量为非负浮点数 |

### 4.2 MediaMetadata

```json
{
  "duration": 18.2,
  "width": 1920,
  "height": 1080,
  "frame_rate": 30,
  "video_codec": "h264",
  "audio_codec": "aac",
  "sample_rate": 48000,
  "channels": 2
}
```

- 视频要求 duration、width 和 height。
- 图片要求 width 和 height，duration 为空。
- 音频要求 duration，视觉尺寸为空。
- width 与 height 同时存在或同时为空。
- 片段的 `source_in + duration` 不超过可计时素材的 duration，比较容差为 `1e-9` 秒。

### 4.3 Transform

```json
{
  "x": 1320,
  "y": 80,
  "width": 480,
  "height": 270,
  "rotation": 0,
  "opacity": 1
}
```

- `x`、`y` 是相对输出画布左上角的像素坐标。
- `width`、`height` 是大于 0 的输出像素尺寸；网页“缩放”控件等比更新两者。
- `rotation` 使用角度，正值顺时针。
- `opacity` 范围为 0 到 1。
- 新增视频或图片片段时，所有 visual 轨统一使用与主视频相同的居中等比适配；轨道顺序只决定层级，不隐式改变片段尺寸或位置。
- 画中画由上层 visual 轨的视频或图片片段与较小 width、height 表达，不占用专用轨道类型。

### 4.4 时间与层级

- 时间统一使用浮点秒，网页显示到毫秒。
- 片段可见区间为 `timeline_start <= t < timeline_start + duration`。
- 分割点必须严格位于片段内部；右片段的 `source_in` 增加左段持续时间。
- 图片与文本分割时保持 `source_in` 原值。
- `tracks` 数组按网页从上到下排列；在所有 visual 轨中，数组位置更靠前者层级更高，第一条 visual 轨是最高视觉层。audio 轨的位置不参与视觉合成，渲染编译器反向遍历并跳过 audio 轨，从最低 visual 轨向最高 visual 轨合成。
- visual 轨承载视频、图片或文本片段，audio 轨承载音频片段。同一 visual 轨内片段重叠时，片段数组靠后的元素位于上层。
- 主画面、画中画、字幕和配乐属于轨道名称或片段用途，不是持久化类型。

## 5. 命令协议

### 5.1 CommandBatch

```json
{
  "expected_revision": 4,
  "commands": [
    {
      "type": "clip.split",
      "track_id": "track_1234567890abcdef",
      "clip_id": "clip_1234567890abcdef",
      "at": 6.4
    }
  ]
}
```

- `commands` 至少一条。
- 批内命令依次应用到同一个内存工程副本。
- 任一命令失败时，整个批次保持原 revision 和原文件。
- 全部命令通过后，新工程 revision 为 `expected_revision + 1`。
- 存储层在排他锁内再次核对 revision，覆盖网页、CLI 和 Python 并发写入。

### 5.2 命令集合

| type | 输入 | 行为 |
| :-- | :-- | :-- |
| `project.update` | `changes.name`、`changes.canvas` | 更新工程名称或画布 |
| `asset.add` | `asset` | 登记已复制并探测的素材 |
| `asset.delete` | `asset_id` | 删除未被片段引用的素材记录 |
| `track.add` | `media_domain`、`name`、可选 `index` | 新增 visual 或 audio 轨；省略 index 时追加 |
| `track.update` | `track_id`、`changes.name` | 修改轨道名称 |
| `track.move` | `track_id`、`to_index` | 调整轨道数组位置与视觉层级 |
| `track.delete` | `track_id` | 删除轨道及其片段 |
| `clip.add` | `track_id`、`clip` | 校验片段种类、素材种类与轨道处理域后新增片段 |
| `clip.update` | `track_id`、`clip_id`、`changes` | 完成拖动、裁剪、文本或 Transform 修改 |
| `clip.delete` | `track_id`、`clip_id` | 删除片段 |
| `clip.split` | `track_id`、`clip_id`、`at` | 在工程秒数处拆成连续两段 |

### 5.3 冲突语义

```text
读取 revision 4
    |
    v
提交 expected_revision 4
    |
    +-- 当前仍为 4 --> 在副本执行命令 --> 锁内核对 --> 原子保存 revision 5
    |
    +-- 当前已为 5 --> revision_conflict
                            |
                            v
                     读取最新工程后重新形成命令
```

服务不自动合并过期命令。Agent 根据 `error.details.actual_revision` 读取最新快照并重新规划。

## 6. Python API

公开入口：

```python
from components.video_editor import VideoEditorService

service = VideoEditorService("output/editor/projects")
project = service.create("城市漫游")
project = service.get(project.id)
updated = service.apply(
    project.id,
    {
        "expected_revision": project.revision,
        "commands": [
            {
                "type": "track.add",
                "media_domain": "visual",
                "name": "主画面",
            }
        ],
    },
)
```

`VideoEditorService` 提供 `create`、`list`、`get` 和 `apply`。输入可使用 Pydantic 模型或映射；返回 `EditorProject`。领域错误统一为 `VideoEditorError`：

```text
code       稳定机器标识
message    中文说明
details    结构化上下文
```

渲染任务服务消费 project ID 与 expected_revision，任务只读取提交时固化的工程快照，不在渲染期间持有工程写锁。

## 7. CLI

安装脚本名为 `video-editor`，模块入口为 `python -m components.video_editor`。

```powershell
uv run video-editor serve --host 127.0.0.1 --port 8765
uv run video-editor project create --name "城市漫游"
uv run video-editor project list
uv run video-editor project show project_92f53b6789abcdef
uv run video-editor asset import project_92f53b6789abcdef input.mp4 --expected-revision 0
uv run video-editor command apply project_92f53b6789abcdef --file commands.json
uv run video-editor render project_92f53b6789abcdef --expected-revision 4
```

- `command apply` 从 `--file`、`--json` 或标准输入读取一个命令批次。
- 标准输出固定为一个 `ok/data` 或 `ok/error` JSON 对象。
- 中文进度写入标准错误。
- 失败使用非零退出码；参数错误也返回统一 JSON。
- `--root` 覆盖默认工程根目录。

### 8.2 响应

成功：

```json
{
  "ok": true,
  "data": {
    "id": "project_92f53b6789abcdef",
    "revision": 5
  }
}
```

失败：

```json
{
  "ok": false,
  "error": {
    "code": "revision_conflict",
    "message": "工程已被其他写入者更新",
    "details": {
      "expected_revision": 4,
      "actual_revision": 5
    }
  }
}
```

HTTP 状态表达传输类别，Agent 分支使用稳定 `error.code`。请求验证错误、未知路由和未捕获异常均转换为 JSON，不返回 HTML 错误页。成功 envelope 在 OpenAPI 中引用具体的 `EditorProject`、`Asset` 与 `RenderJob`，而不是宽泛对象。

### 8.3 素材上传

```text
multipart file + expected_revision
    |
    v
写入工程 staging --> 路径与大小校验 --> ffprobe
    |
    +-- 失败 --> 删除暂存文件 --> error JSON
    |
    +-- 成功 --> 原子移入 assets --> asset.add 命令
                                           |
                                           +-- revision 冲突 --> 删除本次素材文件
                                           +-- 提交成功 --> 返回 project + asset
```

HTTP 只接受上传内容，不接受远端 URL。CLI 从明确本地路径读取并走同一 `import_media` 与 `asset.add` 语义。两个入口都在写入过程中执行 4 GiB 单文件上限，超限删除暂存文件并返回 `media_too_large`；HTTP 状态为 `413`。

## 9. 工程持久化

### 9.1 目录

```text
output/editor/
+-- projects/
|   +-- project_92f53b6789abcdef/
|       +-- project.json
|       +-- .project.lock
|       +-- assets/
|       +-- renders/
+-- render_jobs/
    +-- .worker.lock
    +-- render_92f53b6789abcdef/
        +-- job.json
        +-- project.json
        +-- request.json
```

`project.json` 是工程权威数据。媒体、任务状态和成品位于同一工程边界内；网页会话状态只存在浏览器内存。

### 9.2 原子保存

```text
创建同目录临时文件
    |
    v
UTF-8 JSON + fsync
    |
    v
os.replace(project.json)
```

锁使用 `.project.lock` 的排他创建。服务层先检查 expected_revision，存储层在锁内再次读取并检查，避免两个并发写者同时提交。锁在正常完成与异常退出路径的 `finally` 中删除。

### 9.3 恢复边界

| 状态 | 处理 |
| :-- | :-- |
| 临时工程文件残留 | 打开工程时忽略，不覆盖 `project.json` |
| `project.json` JSON 或 Schema 无效 | 返回 `project_corrupt`，保持原文件 |
| 素材上传后命令失败 | 删除该次新增素材文件 |
| 渲染进程失败或取消 | 删除任务临时 MP4，保留工程和已有成品 |
| 服务重启时任务状态为 running | 标记为 `failed`，错误码为 `render_interrupted` |
| `.project.lock` 修改时间超过 60 秒 | 写入前回收陈旧锁，再尝试一次排他创建 |

工程 JSON 写锁只覆盖 revision 复核与一次原子替换，正常持有时间远低于 60 秒。60 秒内的锁统一返回 `project_busy`，不抢占活跃写者。

## 10. 浏览器工作台

### 10.1 状态划分

```text
服务端工程状态：project、assets、tracks、clips、revision
浏览器会话状态：selectedClipId、playheadSeconds、pixelsPerSecond、isPlaying
拖动草稿状态：时间线 DOM left / width、预览 DOM x / y / width / height，仅 pointer 手势期间存在
```

拖动期间只改变 DOM 草稿；pointerup 转换为一个 `clip.update` 命令。服务返回新工程后，`state.setProject` 替换快照。revision 冲突时读取最新工程并提示用户重做该手势。预览区移动和缩放不会在每个 pointermove 写入工程。

### 10.2 时间线

- 横向尺度由 `pixelsPerSecond` 控制，范围 30 到 180。
- 片段位置为 `timeline_start * pixelsPerSecond`。
- 片段宽度为 `duration * pixelsPerSecond`，视觉最小宽度为 18px。
- 播放头使用 9px 命中区与 1px 视觉线；按下后通过 Pointer Capture 连续拖动，时间坐标包含横向滚动偏移。
- 播放中开始拖动播放头时停止播放循环；播放头时间继续由会话状态钳制到工程时长。
- 裁剪手势最小片段时长为 0.08 秒。
- 左侧裁剪同时增加 `source_in` 并减少 `duration`。
- 素材通过 `application/x-video-create-asset` 拖放数据进入处理域兼容的轨道。

### 10.3 组合预览

浏览器预览不启动 FFmpeg：

- 视频使用 `<video>`，图片使用 `<img>`，音频使用 `<audio>`，文本使用绝对定位 `<div>`。
- 活动片段条件与工程左闭右开时间区间一致。
- `x`、`y`、`width`、`height` 按画布尺寸转换为百分比。
- `rotation` 使用 CSS rotate，`opacity` 直接映射 CSS opacity。
- 当前可见的选中 visual 片段显示独立变换框；拖动框体调整 `x`、`y`，拖动四角控制点按原宽高比调整 `width`、`height`。
- 预览变换使用 Pointer Capture，按实际预览矩形换算画布像素；手势结束时只提交一次完整 Transform，播放中开始调整会先暂停播放。
- 媒体目标时间为 `source_in + playheadSeconds - timeline_start`。
- 离开活动区间的媒体暂停并移除元素，释放解码资源。
- 预览播放以工作台播放头为主时钟，媒体元素跟随校时。

浏览器解码能力只影响预览。ffprobe 可读且 FFmpeg 可渲染的素材保持工程与导出能力，界面显示预览错误状态。

## 11. 渲染管线

### 11.1 持久化单并发队列

```text
POST renders + expected_revision
    |
    v
核对并固化工程快照 --> 持久化 queued 任务
    |
    v
队列工作线程一次领取 1 个任务
    |
    v
compile_render_plan --> FFmpeg 临时 MP4 --> ffprobe
    |
    +-- 成功 --> 原子发布 --> succeeded
    +-- 失败 --> 清理临时文件 --> failed + error
    +-- 进程停止 --> failed + render_interrupted
```

任务状态为 `queued`、`running`、`succeeded`、`failed` 或 `cancelled`。`RenderJob` 保存 `id`、`project_id`、`revision`、`status`、`progress`、`message`、`output_path` 和可选 `error`；首版 progress 在 queued 与 running 为 0，succeeded 为 1，网页以 700ms 间隔查询阶段状态。每个任务目录保存 `job.json`、固化的 `project.json` 与 `request.json`。队列以 `.worker.lock` 保证跨进程单工作线程，避免两个 FFmpeg 进程争抢 CPU、内存和磁盘带宽。

### 11.2 RenderPlan

`compile_render_plan` 将工程快照纯编译为：

```text
argv          FFmpeg 参数元组
filtergraph   可检查的滤镜图
output_path   当前任务临时文件
duration      工程最大片段结束秒数
```

编译顺序：

1. 创建画布背景视频流。
2. 按工程素材顺序建立输入索引。
3. 反向遍历工程轨道并跳过 audio 轨，再按轨内片段顺序执行 trim、setpts、scale、rotate、opacity 与 overlay，使第一条 visual 轨保持最高视觉层。
4. text 片段在 `Transform` 尺寸的透明图层内居中 drawtext，再围绕该矩形中心 rotate 与 overlay；首版字号固定 48、颜色固定白色。
5. 视频内音频和独立音频执行 atrim、时间偏移、volume、48kHz 重采样与 amix。
6. 输出 H.264、yuv420p；存在音频层时输出 AAC。

子进程使用参数数组启动，不通过 shell 字符串。单次 FFmpeg 执行使用一个总 deadline，默认 3600 秒；到期后先 terminate，3 秒后仍未退出则 kill。输出先写任务临时 MP4；FFmpeg 退出码为 0 后，ffprobe 再验证 duration 与视频尺寸，最后使用 `os.replace` 发布。

### 11.3 预览与导出一致性

一致性由工程字段定义，而不是共享运行时：

| 语义 | 浏览器 | FFmpeg |
| :-- | :-- | :-- |
| 时间 | `timeline_start`、`duration`、`source_in` | trim、setpts、enable |
| 几何 | CSS left、top、width、height | overlay x、y 与 scale width、height |
| 旋转 | CSS rotate，原点为矩形中心 | 透明图层 rotate，并按 overlay_w、overlay_h 回补矩形中心偏移 |
| 透明度 | CSS opacity | colorchannelmixer alpha |
| 层级 | 第一条 visual 轨最高，audio 轨位置不参与视觉层级，轨内片段数组靠后者更高 | 反向遍历轨道并跳过 audio，轨内片段正向串联 overlay |
| 音量 | Web Audio GainNode | FFmpeg volume |

固定工程夹具在指定秒数采集网页截图与导出帧，位置容差为 2 像素，片段边界容差为一帧。文本布局受浏览器与 FFmpeg 字体度量差异影响，首版以内容、出现区间、字号和左上角位置为一致性验收项。

## 12. 容错矩阵

| 故障 | 检测 | 状态保护 | 结果 |
| :-- | :-- | :-- | :-- |
| 命令结构无效 | Pydantic 严格模型与判别联合 | 工程副本不提交 | `invalid_input` |
| revision 过期 | 服务层与锁内双检查 | 工程文件保持原 revision | `revision_conflict` 与 actual_revision |
| 同工程并发写 | 排他 `.project.lock` | 只允许一个写者进入提交区 | `project_busy` |
| 工程写入中断 | 同目录临时文件、fsync、os.replace | 读者看到旧完整文件或新完整文件 | 临时文件可清理 |
| 工程文件损坏 | JSON 与 Schema 校验 | 保持原文件，不继续写 | `project_corrupt` |
| 素材路径越界 | 规范化路径与工程根检查 | 拒绝读取与渲染 | `invalid_asset_path` |
| 媒体格式或流无效 | ffprobe 与类型规则 | 不登记 Asset | `unsupported_media` 或 `invalid_media_stream` |
| ffprobe 超时 | 子进程 30 秒时限 | 删除暂存文件 | `media_probe_timeout` |
| FFmpeg 缺失 | 子进程启动异常 | 工程与既有成品保持原样 | `ffmpeg_unavailable` |
| FFmpeg 非零退出 | returncode 与 stderr | 删除任务临时 MP4 | `render_failed` |
| FFmpeg 超过总执行时限 | 单调时钟 deadline | terminate 后按需 kill，删除任务临时 MP4，队列继续 | `render_timeout` |
| 成品验证失败 | ffprobe 检查 duration 与尺寸 | 不发布到下载接口 | `render_output_invalid` |
| 服务在渲染时终止 | 启动时读取持久化任务 | 既有成品保持原样 | running 转为 failed，错误码为 render_interrupted |
| 浏览器断开 | 服务端命令批次独立完成 | 客户端重新读取工程 revision | 最新快照 |

错误详情不记录媒体内容、完整命令载荷、环境变量值和凭证。FFmpeg stderr 只保留固定长度摘要，完整诊断写入任务日志。

## 13. 性能瓶颈与控制

| 瓶颈 | 信号 | 控制 | 劣化动作 |
| :-- | :-- | :-- | :-- |
| 多个活动视频元素解码 | 预览 fps、丢帧率、活动媒体数 | 只保留当前活动片段，离区立即暂停和移除 | fps 低于 45 时降低预览画布尺寸并提示 |
| 时间线完整 DOM 重绘 | pointer 到 paint、节点数、长任务 | 拖动只改目标 DOM；服务回执后统一重绘 | 片段超过 200 时隐藏次要视觉内容；后续接入视口虚拟化 |
| 高频 pointermove 写入 | 每秒命令数、锁冲突数 | pointerup 只提交一次 `clip.update` | 工程繁忙时保留草稿并提示重做 |
| 完整工程 JSON 序列化 | 文件大小、保存 p95 | Agent 将关联操作放入一个命令批次；一次批次只写一次 | 保存 p95 超过 350ms 时记录工程规模 |
| 素材上传与哈希、探测 | 请求内存、磁盘吞吐、探测耗时 | UploadFile 与分块复制，探测有超时，失败文件清理 | 新导入串行并保留已有编辑能力 |
| 滤镜图随视觉片段增长 | 编译时间、argv 长度、FFmpeg 内存 | 预检片段数和输入数，RenderPlan 独立可测试 | 超过 200 片段显示规模提示 |
| FFmpeg 占用 CPU 与磁盘 | API p95、系统负载、实时系数 | 持久化单并发队列 | 当前任务完成前不启动下一个任务 |
| 任务日志增长 | 文件大小与磁盘剩余 | 每任务日志设置 20MB 上限，保留错误尾部 | 达上限后仅写阶段与终态 |

关键预算沿用 PRD 第十章：单命令批次 HTTP p95 不超过 100ms，200 片段工程打开不超过 800ms，时间线反馈 p95 不超过 50ms，双视频层预览至少 55 fps，1080p 导出实时系数不超过 2.0。

渲染器扩展消费 `EditorProject` 的不可变快照并返回持久化任务状态。MCP 或其他 Agent SDK 映射到 `VideoEditorService` 或 `/api/v1`，保持 `CommandBatch`、revision 和错误码不变。框架可替换，工程与命令协议保持稳定。

## 16. 架构红线

- 网页、Python、CLI 和 HTTP 始终使用同一 `EditorProject` 与 `CommandBatch`。
- 网页不直接覆盖 `project.json`。
- 接入层不复制 `VideoEditorService` 的领域校验。
- 浏览器预览不启动 FFmpeg。
- FFmpeg 只运行在持久化单并发导出队列中。
- 源素材、已有工程和已验证成品不进入失败清理范围。
- 未知 `schema_version` 不进入写入路径。
- 新框架、新协议和新渲染器不改变既有工程、命令、revision 与错误码语义。
